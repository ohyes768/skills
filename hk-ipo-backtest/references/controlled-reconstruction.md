# 受控事后重建（PIT 妥协路径）

## 何时走这条路径

当目标 IPO 案例日已成熟、但本地 cron 输出目录（`~/.hermes/cron/output/<job_id>/`）不存在截止点前的 agent 预测快照存档时。不要直接判 `回测无效`，改走"受控事后重建"。

skill 主 SKILL.md § 3a 给了高层流程；本文档是可重用的具体步骤、判定规则与历史教训。

## 判定"快照缺失"

```
~/.hermes/cron/output/
├── <job_id_A>/YYYY-MM-DD_HH-MM-SS.md  ← 任务级快照
├── <job_id_B>/...
├── hk-ipo-daily-YYYY-MM-DD-<code>.md  ← 每日研究产物（不一定含方向预测）
```

注意：每日研究产物（`hk-ipo-daily-...md`）≠ 预测快照。每日研究产物通常是"招股期打分报告"，不区分"预测阶段/验证阶段"，可能含预测超购倍数（动态值）但不一定含冻结的方向预测。真正的"预测快照"必须包含：

1. 明确的截止点时间戳
2. 候选全集（不仅是目标 IPO）
3. 方向预测（暗盘方向 + 开盘方向 + 申购建议 + 置信度）
4. 数据泄漏审计（哪些字段时间可证 / 哪些不可证）

如果本地只有每日研究产物、缺带方向预测的冻结快照 → 走"受控事后重建"。

## 候选全集重建（jisilu 过滤法）

```bash
python3 ../hk-ipo-research/scripts/hkipo.py jisilu list --json > /tmp/jisilu_list.json
python3 -c "
import json
with open('/tmp/jisilu_list.json') as f:
    data = json.load(f)
CUTOFF = 'YYYY-MM-DD'  # 招股截止日前一天
cands = [r for r in data if r['apply_date'] <= CUTOFF <= r['apply_end_date']]
print(f'候选 {len(cands)}:')
for r in cands:
    print(r['code'], r['name'], r['apply_date'], '→', r['apply_end_date'], 'list:', r['listing_date'])
"
```

按 `apply_date ≤ cutoff ≤ apply_end_date` 过滤。这是确定性的，不依赖实时源。

## 预测输入来源优先级（截止点前可证）

| 字段 | 首选来源 | 兜底来源 | 时点要求 |
|---|---|---|---|
| 招股条款（招股期、发行价区间、每手、入场费） | HKEX 招股章程 PDF（仅核验） | 招股首日及之后的中文媒体（新浪财经 / 东方财富 / 财联社 / 智通财经） | ≥ 招股首日 |
| 全球发售规模 / 公开 / 国际比例 | 招股书 + 招股期媒体 | jisilu 历史 | ≥ 招股首日 |
| 财务三表 / 毛利率 / 亏损 | 招股书披露（招股期前的招股书更新）+ 招股期内媒体转引 | — | ≥ 招股首日 |
| 业务定位 / 市占率 | 灼识咨询口径（招股书 + 招股期内媒体） | — | ≥ 招股首日 |
| 创始人 / 实际控制人 / 主要股东 | 招股书 + 招股期内媒体 | 招股前的多轮融资新闻 | ≥ 招股首日 |
| D+ 轮估值 / 累计融资 | 招股期前 6 个月的财经媒体（新浪财经 / 36 氪 / 投中网） | — | ≥ 招股期前 |
| 保荐人 | 招股书 + 招股期媒体 | jisilu 历史标签 | ≥ 招股首日 |
| 基石投资者 | 招股书"基石投资者"章节 | 招股期媒体确认 | ≥ 招股首日；如"无基石"也需在招股书或媒体显式披露 |
| 关键诉讼 / 监管事项 | 招股书"风险因素" + 招股期前 6 个月公开判决书 / 媒体 | — | ≥ 招股期前 |
| **孖展数值** | TradeSmart 招股中实时（**仅 `observed_at` ≤ 截止点**） | 招股期内的中文媒体定性报道（"认购情绪高涨"/"超购 X 倍"等） | **必读 observed_at** |
| **券商 13+ 分项** | TradeSmart 孖展分项（截止点前快照） | 暂无可证源 | 同上 |
| **机构评级 / 目标价** | 招股期内的卖方研报（华泰 / 招银 / 广发等港股研究） | — | ≥ 招股首日 |

## TradeSmart `observed_at` 判定流程

```bash
python3 ../hk-ipo-research/scripts/hkipo.py tradesmart tracker <CODE>
# 输出形如：
# {
#   "observed_at": "2026-08-06T15:05:15.097Z",
#   "margin_total_hkd_yi": 1712.23,
#   ...
# }
```

转 HKT：`2026-08-06T15:05Z` = `2026-08-06 23:05 HKT`。对比截止点：

- `observed_at_HKT` ≤ `截止点` → ✅ 可用，标注具体时间戳
- `observed_at_HKT` > `截止点` → ❌ 未来数据，**不得进入方向判断**；只能承认定性热度（"招股期热度持续极热"），具体数值从打分中剔除
- TradeSmart 没有时间回溯 API；本地若无截止点前的快照存档，孖展数值整体不可证

## 报告模板差异（vs. 严格 PIT 回测）

受控事后重建的报告必须在 § 回测状态 显式标注 `受控事后重建`，并在 § 数据泄漏审计 用三栏表格列出每个输入字段的 PIT 状态：

| 输入字段 | 来源 | 截止点前可证? | 处理 |
|---|---|---|---|
| 招股条款 | HKEX 2026-07-30 | ✅ | 用于预测 |
| 财务数据 | 新浪财经 2026-05-19 | ✅ | 用于预测 |
| 8/3 孖展数值 | TradeSmart（observed_at 8/6） | ❌ 时间不可证 | 仅定性承认热度，不进入打分 |
| 最终定价 / 暗盘 / 首日 | 各源（8/6 22:12 后） | ❌ 未来数据 | 仅用于验证阶段 |

## 置信度降级

受控事后重建的置信度最高为"中"，不得标"高"或"极高"。理由：核心热度输入不可证、券商分项缺失、券商 13+ 分项未取得。

## 历史教训

- **2026-08-07 拿森科技（02261.HK）回测**：本地无 8/3 23:59:59 时点的方向预测快照，但 jisilu list 在 8/3 时点只有 02261 一只候选，可确定性地重建候选全集；招股书、招股期媒体均能多源核验；最终成功完成受控事后重建并推送 RSS（ID `20260807-160641-b42ec2`），命中结论"部分命中"。如果当时直接判 `回测无效`，会错过唯一成熟案例。
- **cron 应在每个招股截止日 23:59:59 前预先保存一份带方向预测的快照**，这样后续可在严格 PIT 模式而非受控重建模式下做回测。

## 与"回测无效"的区别

| 状态 | 何时使用 | 后续动作 |
|---|---|---|
| **回测无效** | 招股截止日不可核验 / 候选全集明显不完整 / 关键预测输入完全无法证明在截止点前存在 | 输出缺口列表，不推送 RSS |
| **受控事后重建** | 本地无冻结快照但截止点前可证公开数据充足 | 标注状态、降级置信度、推送带 quality_warnings 的 RSS |
| **严格 PIT 回测** | 本地有截止点前的冻结预测快照 | 满置信度推送 |

`受控事后重建` ≠ `回测无效`：前者保留审计价值，后者宣告作废。
