## 三、本次新增的可复用经验

### 3.1 新增 PITFALL #41：「公佈售股結果日 / 暗盤日」≠「首日交易日」

10/27 的港股新股事件全部落在 02384 的**上市前一日**环节。当日三件事同时发生：

| 环节 | 日期 | 陷阱 |
|---|---|---|
| 定價 | 10/26 | — |
| **公佈售股結果** | **10/27** | 配发结果、中签率公布日 → 看起来像「事件日」 |
| **暗盤** | **10/27 16:15–18:30** | 暗盘有涨跌幅 → 看起来像「首日行情」 |
| **正式上市（首日交易）** | **10/28** | ← 才是回测案例日 |

**判别式**（按可靠性排序）：
1. **AAStocks per-code 招股日程的「上市日期」列** —— 最直接的权威字段（`company-summary?symbol=<code>` 的「招股日程」四段：招股日期 / 定價日期 / 公佈售股結果日期 / 上市日期）。**本批首次把 AAStocks per-code 当作一手日程源使用**，比依赖 jisilu `listing_date` 更稳（jisilu 对延迟票会保留原定日期，见 PITFALL #40）。
2. **暗盤时段判断**：AAStocks「即將上市」栏会标「今日暗盤」，并在页头给出「(暗盤交易時段:今日16:15-18:30)」。**「今日暗盤」⇒ 今日不是上市日**。
3. **公告原文**：「公司预期将于 X 年 X 月 X 日按招股章程『如何申请香港发售股份 — 公布结果』所述方式公布…」→ 这句是**公布结果日**，不是上市日。

**推论**：回测 cron 的「今日是否成熟」判定，**在 AAStocks per-code 可得时优先用其「上市日期」列**，而不是 jisilu `listing_date`。原因：延迟票（03275）在 jisilu 里的 `listing_date` 是错的（仍 = 10-28），而 AAStocks 的日程列在延迟后会变（03275 的 AAStocks 行显示 `2026/10/28` 但 AAStocks 已在「即將上市」移除它并标「微億智造 03275.HK」为已延迟条目 —— **需人工看上下文，不能单看日期字段**）。

## 五、经验提炼

- **10 月末流水线占满整条链**：10/20–10/23 招股 → 10/26 定价 → **10/27 公布结果 + 暗盤** → **10/28 上市**。今日处于「上市前一日」，无首日交易是结构性的，不是数据漏报。
- **「公布结果日 + 暗盤日」容易被误当成案例日** → 明日 10/28 才是 02384 的回测案例日，其预测截止点 = **2026-10-22 23:59:59 HKT**（招股截止 10/23 的前一自然日），本地已有 `hk-ipo-daily-2026-10-22-02384.md` 可作快照。
- **AAStocks per-code 的「招股日程」是本批新发现的一手日程源**，含「定價日期 / 公佈售股結果日期 / 上市日期」三段明确日期，比 jisilu `listing_date` 可靠（后者对延迟票是错的）。
- **审计 cron 的交付策略**：有实质发现 → 输出摘要 + 写留痕；连续多日零发现 → 应转 `[SILENT]`。
