# 财报 Skill Hermes 运行流程收敛与耗时优化

## Goal

保留A股单份PDF到中文Markdown的分析能力，减少MiniMax-M3在Hermes上手写合同、猜引用、研究实现和反复修复的开销。运行时不得修改检查规则或把未通过结果冒充通过。当前只规划，不修改业务脚本、不部署、不发送消息。

## Background and Evidence

导出记录run_86e78479e57d465a8ead9969e1bf7695（凡拓数创）：190条消息、97次工具调用、90次模型API调用，跨度759.9秒；首次报告校验后仍花346.4秒、29次工具调用，最终达到迭代上限。初次financials写入66148字符；schema检查7次、指标计算3次、报告校验4次。观察到修改规则的想法，但未发现实际写入校验器的工具调用。

现有10个Python文件：6个流程CLI和4个公共模块。下载/索引/提取/读包/计算/校验均实际使用；缺少统一编排、紧凑事实构造和报告/claims共同生成。详见research/runtime-evidence.md。

## Requirements

- R1 输入、输出和分析范围兼容。不得减少必要财务覆盖或跳过校验来换速度，不按fact数量判断质量。
- R2 模型只提交需要判断的事实映射和分析陈述，不再手写重复字段、维护页码集合或重写算法。保留报表范围、归属、期间、币种和重述边界，不确定项明示。
- R3 数值陈述与来源绑定，正文与claims同源生成。派生值有公式和输入，披露值有证据。禁止按数值碰巧相同反向寻找支持事实。
- R4 分析运行不修改scripts、references、Skill、依赖或校验结果。事实修复依据原文，manifest仅由提取程序更新；实际权限由宿主执行，仅靠提示词不算完成。
- R5 错误反馈有定位和原因；最多两轮集中修复，不无限重试。源码/依赖/校验器故障属于维护问题，不在分析任务内修程序。
- R6 区分结构性数字、财务数量、页码、百分比和百分点；支持常见合法表达，同时拦住错误金额、比例与来源。
- R7 复用下载/索引、按需补提取，analyze/review不重复交付全部原文。记录模型/工具轮数、阶段耗时、重复读取量和可得usage；不可得时不编造费用。
- R8 区分已验证完成、验证未通过/数据不足、需要维护；未通过结果不走正式发布成功分支。Skill不直接发钉钉/RSS，发布归调用端。

## Acceptance Criteria

- [ ] A1 六个现有流程步骤通过新入口串联，干净目录、缓存复用、增量回查有离线集成测试（R1/R7）。
- [ ] A2 紧凑事实生成完整合同；missing_reason、half_year、cost_of_sales无需模型猜；归属和现金等价物含义不可静默改写（R2）。
- [ ] A3 同源生成正文/claims；篡改正文、错误证据/维度/金额仍拒绝；派生指标可追踪（R3）。
- [ ] A4 复现修复3D、2026上半年、56-57页、下降正幅度和百分点误报，错误比例/符号/页码负例仍拦截（R6）。
- [ ] A5 初检加最多两次修复后停止；重启/重复调用不重置预算；反馈有计数和定位样例（R5/R8）。
- [ ] A6 同一agent凭据无法写脚本/可信校验结果；无法隔离时预检不声称受保护运行（R4）。
- [ ] A7 保留现有160例基线并补回归，Ruff和元数据校验通过；不得删除旧负例放宽规则。
- [ ] A8 固定PDF/模型/环境做全程对比；目标工具轮数较97减少至少40%、输出token减少至少30%，必要覆盖和拦错能力不降低。尚未验证，不承诺固定分钟数（R1/R7）。

## Out of Scope

不换模型、不重写通用PDF/OCR引擎、不硬限事实数量、不改Hermes核心API、不扩大审批豁免、不补发历史消息。其他仓库接入与宿主隔离需独立执行验收。
