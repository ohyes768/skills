# F10 财报分析：减少源码探索并完善分析证据与运行效率

## 目标与授权

依据恒工精密 301261 / 2026-09-30 的 Hermes 会话复盘，减少源码探索、临时计算和成功后的重复复核，完善定性判断证据。本次仅建档，保留 planning，不启动实现、不部署、不发布消息。

## 背景

会话跨度 536.6 秒、50 次工具调用、41 次 API 调用。取数计算在约第 17 秒成功，骨架约第 59 秒生成；正式报告一次通过 440 项检查，但存在覆盖误述和归因过强。证据详见 research/session-evidence.md。

关联旧任务：10-19-financial-analysis-hermes-runtime、10-21-financial-analysis-structured-source。本任务跟进 F10 上线后的剩余问题，不重开 PDF 路径，不改关联任务状态。

## 需求与优先级

| ID | 优先级 | 需要优化的行为 |
| --- | --- | --- |
| R1 | P0 | 区分接口无记录、请求失败、字段缺失、未映射、未计算及未提供给模型；不能把比较指标缺少写成报表未取得。 |
| R2 | P0 | 重大定性归因有证据与限定；利润驱动、资产转固和杜邦同比不能仅凭余额方向或不完整比较数据推断。 |
| R3 | P1 | 写作待办明确可编辑段落、句数余量、数字规则、可用证据和缺失限制，正常分析无需研究源码。 |
| R4 | P1 | compute 首包与续页合同一致，游标完整消费；紧凑分析包支持常规写作，无需手抄数字、自写公式、扫描全部原始字段。 |
| R5 | P1 | verified 且 terminal=true 后停止工具循环；维护故障进入维护路径，区分 skill 提示与宿主执行边界。 |
| R6 | P1 | 可比较阶段耗时、调用轮数、源码访问、重复读取及可得 usage，优化不减少财务覆盖和验收。 |

## 验收标准

- [ ] A1（R1）：本次九份三表样本下，不再声称比较期资产负债表未取得；分别覆盖 no_data、fetch_failed、字段 null、未映射及未计算情形。
- [ ] A2（R2）：利润变动桥有来源、输入、差额和缺失状态，不把 null 当零；无支持的主要归因、确认转固、同比改善应被阻止或明确降级。人工语义复核仍保留。
- [ ] A3（R3）：每个待办直接给出写作约束；保留四条核心 statement 时明确剩余句数；正常回放源码读取为零。
- [ ] A4（R4）：首包到末页无需猜测 envelope，无遗漏；比较期、风险和覆盖摘要充分，来源身份可查。
- [ ] A5（R5）：终态后没有模型追加工具调用；独立复算、来源校验和持久修复预算保持。宿主未实施部分明确列作依赖，不声称全链路完成。
- [ ] A6（R6）：同一留档、MiniMax-M3.1-flash 下至少三次回放，报告耗时中位数/范围、工具/API 次数、源码访问、可得 token 与语义质量；目标工具次数较 50 减少至少 40%，属待验证目标，不承诺固定分钟数。
- [ ] A7：现有来源、维度、数值负例保留，skill 测试、Ruff、元数据及消费兼容性检查通过；不能放宽验收换速度。
