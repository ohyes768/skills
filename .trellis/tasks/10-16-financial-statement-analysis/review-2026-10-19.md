## 优先修复：P1

### F01：定向补提取会删除旧证据，并使旧 ID 指向新页面

位置：`scripts/extract_sections.py:128-134`、`268-273`。

每次调用先删除 excerpts 下所有文件，再将证据编号从 ev-0001 开始并覆盖清单。这与 skill 第 8 步的“按页补提附注”直接冲突。

实测：先提取合并资产负债表，得到 3 条证据，ev-0001 指向 PDF 第 9 页；随后只补提第 12 页，清单只剩 1 条，ev-0001 改指第 12 页，旧文件被覆盖。已有 financials/metrics/claims 的引用会悬空或错误绑定，而 ID 存在性检查可能仍通过。

建议：默认采用增量、原子更新；证据 ID 绑定文档版本、页码/区域及提取类型。同一来源重跑可幂等更新，新页不能复用别页的 ID；整体重置应显式选择，并处理下游失效。

### F02：指标独立取最新值，允许跨期、跨币种计算；同比不要求上年同期

位置：`scripts/calculate_metrics.py:65-98`、`152-173`；FCF 等调用也受影响。

实测：删除 2024 年集团利润后，净利率仍 computed，采用 2023 年利润 80 / 2024 年收入 1200 = 6.67%。把收入币种改 USD、利润保留 CNY，仍计算。将比较收入改为 2024 上半年 1000，本年全年 1200 被标成同比增长 20%。

建议：先确定报告目标期间和范围，再绑定所有输入。同比匹配上一年度相同期间；比例和差额匹配 start/end、frequency、aggregation、scope、归属、currency/unit、可比版本。不匹配时降级，不退回另一年度的“最新可用数”。

### F03：平均余额和现金余额绕过合并/归属筛选

位置：`scripts/calculate_metrics.py:101-121`、`307-329`。

实测：将核心样例的权益全部改为母公司、归母口径，集团利润保持原样，集团简化 ROE 仍 computed=15%，且引用母公司权益。合并和母公司同时出现时，还可能制造虚假 conflict。资产、应收、存货平均余额以及现金勾稽存在相同问题。

建议：余额函数显式接受目标范围和流量期间，取相应期初/期末；不能仅按科目和最近两个日期取值。统一使用经过维度核对的事实选择器。

### F04：合同允许的缺失值会崩溃，未核验事实也被计算为确定值

位置：`scripts/calculate_metrics.py:24-30`、`65-75`、`141`、`171`。

实测：将收入改为合法的 `value=null, review_status=missing, missing_reason=not disclosed, evidence_ids=[]`，合同检查通过，但 calculate_metrics 抛出 None 转 Decimal 的 TypeError。将事实 review_status 改为 conflict，则仍生成 computed 的同比和净利率。

建议：选择与计算阶段传播 missing/ambiguous/conflict；缺失输出 insufficient_data，冲突阻断相关指标。不要仅在输入 JSON 合同中允许这些状态。

### F05：报告校验没有读取交付的 analysis.md

位置：`scripts/validate_report.py:59-65`、`80-139`；CLI 在 `150-155` 仅检查正文文件存在。

实测：保留正确台账，正文写成完全不同的“Revenue declined 88%, no sources.”，校验仍 passed；claims 为空也可 passed。report_anchor 未用于检查正文。现有通过测试的默认正文只是“正文。”，不能验证正文与台账的一致性。

建议：让正文关键陈述与 claim_id 有稳定映射，检查 anchor/数字/引用确实出现在相应正文位置；要求关键指标和结论的台账覆盖。空台账不能证明完整分析通过。机器验收不能只检验 agent 另写的一份清单。

### F06：数值校验会放过十倍、百倍错误

位置：`scripts/validate_report.py:17-42`。

实测：`_text_contains_value('Growth 2%', Decimal('.2'))` 为 True。原因之一是整数 20 被 `rstrip('0')` 改为 2；此外不检查百分号就尝试将任意文本数字除以 100，所以指标 100 与正文金额 10000 也能匹配。

建议：保留整数尾零；区分比率、百分数、金额、显示单位和舍入精度，按字段及单位比较。金额不得默认尝试百分比解释。

### F07：事实数字和页码证据链没有被真正核对

位置：`scripts/validate_report.py:68-75`、`96-119`。

实测：收入事实为 1,200,000,000，但 fact claim 写 Revenue is 999 yuan，保留有效 ID 即可 passed；ev-0001 位于第 9 页，claim 改引第 1 页也 passed。引用 insufficient_data/conflict 的 metric 还可以仅凭 ID 存在被视为有支持。

建议：从 claim 追溯 metric→fact→evidence，核对值、可用状态、文档哈希及页码对应关系；“页码未越界”不等于“引用正确”。与 F05 的正文映射共同完成确定性的证据闭环。

### F08：按 skill 顺序，首次定位章节就会报错

位置：`scripts/pack_context.py:33-34`、`124-132`；`SKILL.md:19-22`。

skill 规定 inspect 后先 locate，再 extract；但 locate 无条件读取 extraction_manifest.json，只有 extract 才生成该文件。

实测：新运行目录已有 sections.json，但无 extraction_manifest.json 时，locate 抛 FileNotFoundError。

建议：locate 只要求章节索引；提取清单不存在时返回空证据索引。增加从空目录按文档步骤调用的真实 CLI 集成测试。

### F09：混合页保存的 PNG 被按 UTF-8 文字读取

位置：`scripts/pack_context.py:109-120`；图片产物来自 `scripts/extract_sections.py:182-200`。

实测：混合页产生 text 和 image_crop 两类证据，map 将非 table 全部按文字打开，读取 PNG 首字节 0x89 即 UnicodeDecodeError，整包中断。

建议：按 kind 分派；图片返回路径、页码、区域及待视觉读取状态，由 agent 按需看图。不能既把图片当作已完整提取，又把二进制按文本解码。

## 后续修复：P2

### F10：下载缓存没有绑定请求 URL，也不自动重检更新

位置：`scripts/fetch_pdf.py:122-125`。

实测：同一 output-dir 先请求 a.pdf 再请求 b.pdf，HTTP 只访问 a.pdf，第二次返回 a.pdf 的 source.json 且 reused=True。公司+年度的目录还无法区分修订版和不同报告类型。

建议：缓存绑定来源和文档版本，至少核对 requested_url/final_url；结合条件请求或明确的缓存策略处理同 URL 更新。换源或刷新后应使旧索引/事实等产物失效。

### F11：locate 绕过上下文包上限

位置：`scripts/pack_context.py:185-218`。

实测：100 条证据的 locate 包为 16,898 字符，默认 max_chars=12,000，但无报错且 next_cursor=null。locate 绕过分包循环，最终也没有统一上限校验。

建议：所有 stage 使用同一序列化后预算与游标。拆块使用当前 max_chars，而不是固定 DEFAULT_MAX_CHARS；同时测试大量索引、特殊字符、长表格行及自定义小预算。

### F12：缺失/冲突指标未使 CLI 报告 partial

位置：`scripts/calculate_metrics.py:454-458`。

实测：合法空 facts 使全部指标 insufficient_data，但 CLI 返回 0、status=ok、issues=[]。当前 problems 只统计现金检查，且忽略 not_applicable。

建议：完成状态区分行业不适用、正常未披露与影响核心结论的数据不足；将核心缺失和冲突列入机器可读 issues，避免 agent 把脚本成功当成分析完整。

### F13：上期冲突默认取第一条

位置：`scripts/calculate_metrics.py:93-98`、`117-120`、`324-329`。

实测：同一 2023 比较期同时有收入 1000 和 900，合同通过；同比仍 computed，结果随列表顺序改变。当前期检查冲突而比较期未检查。

建议：本期、比较期、期初与期末使用相同冲突检查，并明确重述版本选择。等值重复记录也要按不同日期数量检查，避免 ends[1] 越界。

### F14：未披露的汇率影响被当作零并允许现金勾稽通过

位置：`scripts/calculate_metrics.py:363-365`。

实测：删除汇率影响事实，设置期末为不含汇率项的合计后，cash_reconciliation 输出 passed，只在 issues 写 treated as 0。

建议：区分明确披露零、不适用和未披露；资料不足时只给可验证部分，不给完整勾稽通过结论。

### F15：文档要求的页码范围不能被 pack_context CLI 解析

位置：`scripts/pack_context.py:273`，对照 `references/analysis-framework.md` 的回查命令。

提取器支持 `--pages N-M`，分析框架也要求以同样形式读包，但 pack_context 只对逗号分割项调用 int，N-M 产生 ValueError，并且发生在错误处理 try 之外。

建议：提取和打包共用页码选择器，支持同样的列表/范围与边界检查。

## 优化方向与测试建议

1. 先修复 P1 并补充以上负例，特别是首次 locate→extract→map→补提→再次 map 的完整链路。现有 e2e 主要断言旧验收 JSON，无法证明当前代码重跑仍成立。
2. 为财务事实建立统一的“可用性+维度”选择层，所有比例、平均余额、同比和勾稽共用；不要逐个指标补独立判断。
3. 按阶段定制包：locate 给索引，map 给证据，analyze 优先给标准化事实/指标，review 给待核对陈述及关联证据。当前 map/analyze/review 走同一原始证据路径，容易重复装载。
4. 成本验收从全新运行目录计入定位、映射、分析、复核和补提的全部实际交付；现有 78.3% 是指定最小读取序列的字符削减，不能外推为真实模型 token/费用削减。
5. 补齐设计要求的资产=负债+权益、适用的利润项目合计等检查；当前 validation 仅调用现金勾稽。毛利率、杠杆/偿债、扣非等指标的计算覆盖也应明确哪些已实现、哪些仍依靠 agent。
6. 加强合同的有限数值、有效日期、期间顺序及单位一致性验证。Decimal 能构造 NaN/Infinity 不代表它们是合法财务金额。
