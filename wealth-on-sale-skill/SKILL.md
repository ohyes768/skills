# 在售理财筛选（招银自营 + 杭银自营）

**开始前先问清楚用户：查招银自营的还是杭州银行（杭银理财）自营的？** 两者数据源和脚本不同。代销渠道（招行代销的光大/民生/信银等）不在本 skill 范围内；相关研究代码已移至 `~/study/wealth-distribution-channel/`，不要在本 skill 里使用。

工作流分三步：**先筛（哪些能买）→ 再查基本面（成立多久）→ 满足条件的才算业绩指标**。所有脚本在 `scripts/` 下，依赖：`requests`、`numpy`、`gmssl`（招银净值接口 SM4 签名需要，`pip install --user gmssl`）。

## 第一步：筛可买产品

```bash
# 招银自营（仅招银自家产品，代销已默认排除），个人可买 R1/R2：
python3 scripts/on_sale_cmb.py --retail --risk R1,R2
#   --retail  排除大额存单(≥20万)、机构专享、私行/私募/尊享
#   --risk    R1~R5，可逗号分隔；不加则全等级
#   --manager 按名称关键字过滤

# 杭银理财（窗口开放=今天能买入）：
python3 scripts/on_sale.py            # 今天窗口开放的
python3 scripts/on_sale.py --all      # 全部在售状态
python3 scripts/on_sale.py --risk R2  # 按风险过滤
```

输出含：代码、风险等级、常开/募集期、发售日期、期限、名称。招银自营代码为 4-6 位数字（可带份额字母，如 120053A、8914）。

按持有期筛选用 `--min-days N`（脚本解析，勿手工文本匹配）：
- 持有期优先从**产品名**解析（「180天持有期」「最低持有360天」），因为常开产品的 `term` 字段「365天以上」指**产品存续期**而非持有期；
- 名称无持有期时回退 `term` 字段（封闭式的 term 即封闭期，「181天-365天」取下界、「365天以上」取 365）；
- 日开/天天/活期/现金管理类视为零锁定，`--min-days` 下自动排除。
另注意：期限为「365天以上」的**募集期封闭式**容易被手工正则漏掉（如招睿增利指南针封闭38号），用 `--min-days` 可避免。

## 推荐输出规范

当用户要"推荐/选哪个"时，固定输出三段，不要只给结论：

1. **先列全量**：把满足用户条件（期限/风险/金额门槛）的候选**全部列出**（代码、风险、常开/募集期、**发售/开放起始日期**（`beginDate`）、期限、名称），让用户看到完整筛选面；
2. **业绩只用可信数据**：成立 <6 个月的份额本身不输出指标，用同系列成立 1 年+ 老份额的指标做参照（见下节）；整个系列无 1 年以上老份额的，明确标注"无业绩可参照"；
3. **推荐至多 3 个并逐个给理由**：每个推荐给出系列参照业绩（成立年化/最大回撤/Sharpe）+ 期限流动性考量 + 说明落选者为什么落选。数据注明截至日期，附"仅供参考，不构成投资建议"。

## 第二步：查成立时长等基本面

净值接口会一并返回成立时长，直接进第三步即可（招银自营 D07 份额走 cfweb，杭银走官网 JSON）。

## 第三步：业绩指标（仅成立 ≥ 6 个月的产品）

**规则：成立不足 6 个月的产品不算年化/回撤/Sharpe**——新发理财建仓期净值平滑爬升、未经历债市调整检验，短期年化必然虚高、Sharpe 无意义，直接向用户说明"新品不比业绩，看管理人+策略+基准"。

```bash
cd scripts/
python3 nav_stats.py 120053A 120084A [更多招银/杭银代码]
# 输出: 成立时长、近6月年化、成立年化、最大回撤、成立Sharpe、近1年Sharpe
# 无风险利率按 1.5%；净值缓存写 data/nav_history/<CODE>.csv
# --no-refresh 用本地缓存
```

支持代码：招银自营销售代码（如 120084A、13265D）、杭银 TYG/JQB/HYG 内部码（`code_convert.py` 自动识别）。

## 业绩比较基准

招行列表接口的 `rateLow/rateHigh` 对指数型基准是 0，文字基准需开 `https://cfweb.paas.cmbchina.com/personal/saproductdetail?type=prodintro&saaCod=D07&funCod=<代码>`（JS 渲染，需浏览器截图/快照读取）。典型结构为"15%×活期+8x%×中债短债指数+权益敞口"。

## 判断门槛速查

| 指标 | 最低门槛 | 勉强可信 |
|---|---|---|
| 成立年化 | 3个月 | 6个月+ |
| 最大回撤 | 6个月 | 1年 |
| Sharpe | 1年 | 2年+ |

想对比"未来会像什么样"，优先用**同系列成立 1 年以上的老份额**算指标，而非新份额。

## 同系列老份额参照（新份额必做）

新份额（成立 < 6 个月）的年化/回撤/Sharpe 是建仓期虚高，**不要输出给用户**。推荐理由应建立在同系列成立 1 年以上老份额的真实业绩上：

1. 先查招行产品目录（`on_sale_cmb.fetch_all()`，现存约 770 支自营，含存续老份额）：按系列名关键字（如「招睿明裕」）搜，按 `beginDate` 排序找最老份额。
2. 老份额若已不在招行渠道发行，用 web 搜索产品全名找老份额代码（如 665593=安悦370天1号、130052A=明裕180天持有2号），老份额销售代码同样能走 `nav_stats.py` 拉净值。
3. 若整个系列无 1 年以上老份额（如招睿增瑞），明确告知用户"该系列无历史业绩可参照"。
4. **"同系列"必须同登记编号（杭银看 `dengjino`、招银看系列名逐字匹配），不能拿同家族不同产品线充数**：同一策略前缀下常有并行产品线（例：杭银"丰鸿固收371天XXXXX期" 与 "丰鸿固收（灵动目标盈）XXXX期"是两条独立线，登记编号不同、期限序列不同）。拿错参照=给出虚假业绩背书；两条线都要各自查老份额，查不到就各自标"无业绩可参照"。
5. 参照老份额时注意**风险等级的历史变化**：老份额当年可能是更高风险等级（如丰鸿系 2026-06 前的份额是 R3 中风险，之后才降标 R2），要向用户说明参照份额与本期风险等级可能不完全对应。
6. **typeinfo 等内部字段可作策略指纹**：杭银 typeinfo 中 `b5` 表示含转债/弹性敞口（固收+），同带 b5 的产品线即使标 R2，波动也明显高于纯固收（b2/b3）线；推荐 R1/R2 稳健型用户时优先纯固收线。

## 注意事项

- 招行接口限频时换时间重试
- **中国理财网（cw_chinawealth.py）2026-11 实测失效**：`prod/search` 返回 `code:-1 "二次校验参数不能为空"`——服务端加了新的二次校验参数，现有 RSA+AES 签名过不去，**不是限频**，重试无意义；待重新逆向后修复
- 代销产品净值不在招行披露的（建信/中邮/农银/工银/浦银/华夏等），不要硬试官网（不可达或加密）；能查的只有列表基本信息
- 民生系例外：官网 `BTAProductQry` 直连可用（见 MsResolver）；信银 AF/BF 走 wechat 站可用
- 输出注明数据时间；业绩仅供参考，不构成投资建议
