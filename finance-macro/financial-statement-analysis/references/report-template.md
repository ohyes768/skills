# Report Template

主交付物是运行目录下的 `analysis.md`，由 `render_report.py` 从 `report_inputs.json` 同源生成——不手写正文。中文 Markdown；数字与来源页码全部由绑定自动带出。

## 引用格式（渲染器自动处理）

- statement/table 绑定渲染后自动附加 `（PDF第N、M页）`，页码来自绑定事实的证据页集合；`cite_pages: false` 可关闭。
- 自由段落（paragraphs）**禁止出现任何数字**——包括年份与"PDF 第 N 页"页码引用：无 claim 覆盖的段落里，页码同样会被判为未覆盖数字。指代位置写"详见下表来源标注"这类无数字表达。
- 公司解释与本次判断分开陈述；不为推断伪造原文结论，不写入未披露的预测值。

## 报告结构

```markdown
# <公司名称>（<股票代码>）<报告结束年份>分析

- 来源：<PDF URL>（SHA-256 前 8 位：<hash>）
- 币种与口径：人民币 / 合并口径；全文报告 / 摘要；审计状态
- 分析覆盖：<已读章节清单>；<未覆盖部分及原因>

## 核心结论
（3-5 条有证据的判断：经营变化、盈利质量、现金与偿债、主要风险）

## 主要报表数据
| 指标 | 本期 | 比较期 | 变化 | 来源 |
|---|---|---|---|---|
（金额统一展示单位；来源写 PDF 页码或"本次计算"）

## 关键比率与计算口径
（派生指标与本次计算公式；每个数值注明单位，缺数据时说明不可计算）

## 经营与三表分析
（业务驱动 → 收入与利润 → 资产负债结构 → 现金流）

## 盈利质量与杜邦分解
（CFO/净利润关系、扣非/归母、杜邦三因子及驱动；计算口径与适用限制）

## 风险信号
| 信号 | 状态 | 证据 | 解释与关注点 |
|---|---|---|---|
（状态 ∈ 触发 / 已检查未发现 / 资料不足 / 行业不适用）

## 数据质量评估
（三表勾稽、合并/母公司口径、单位与比较期核对；未核对项说明原因）

## 未验证事项与后续观察
（数据缺失、冲突、两轮回查未解决项、需要历史报告才能判断的问题）

## 来源与计算说明
（主要指标的计算公式与输入页码；OCR 或降级提取说明）
```

## 分寸要求

- 报告中分清"公司解释""原文数字""本次计算""分析判断"四类陈述。
- 部分提取失败时仍可交付，但必须在开头标注"分析不完整"，受影响指标和结论缺省或降级。
- 下载失败、文档不可读、公司/期间无法确认时输出失败说明，不输出貌似完整的分析。
- claims 由渲染器从绑定自动生成：定量内容必须走 statement/table 绑定（`calculation` 有 metric 绑定、`fact` 有 fact 绑定），段落只留纯定性文字。渲染失败清单见 `render_issues.json`（带 statement/行/段落定位），修复 `report_inputs.json` 后重跑。
- 无法计算、冲突或缺失的数据写成"资料不足"等文字，不能以数值参与结论。旧报告与旧台账若不一致，需要重新渲染，不能直接复用旧版校验结果。
- 核心结论必须为第一节且共 3–5 句，覆盖业绩、盈利和主要风险；所有表格行列数与表头一致。
- 按[可复用工具](reusable-tools.md)生成输入，最终用 `report --independent-review` 将独立复核并入交付命令，成功后不再追加 review。
