# Report Template

主交付物是运行目录下的 `analysis.md`。中文 Markdown；关键事实随文引用 PDF 来源页码，计算结论引用输入数据页码，推断说明推断依据。

## 引用格式

- 原文事实：`（PDF 第 N 页）`；支持锚点时 `（[PDF 第 N 页](<原始URL>#page=N)）`。
- 计算结论：`（本次计算，输入见 PDF 第 N 页、PDF 第 M 页）`。
- 公司解释：`管理层解释（PDF 第 N 页）：...`，与本次判断分开。
- 不为推断伪造原文结论；不写入未披露的预测值。

## 报告结构

```markdown
# <公司名称>（<股票代码>）<报告结束年份>分析

- 来源：<PDF URL>（SHA-256 前 8 位：<hash>）
- 币种与口径：人民币 / 合并口径；全文报告 / 摘要；审计状态
- 分析覆盖：<已读章节清单>；<未覆盖部分及原因>

## 核心结论
（3-5 条有证据的判断：经营变化、盈利质量、现金与偿债、主要风险）

## 关键指标
| 指标 | 本期 | 比较期 | 变化 | 来源 |
|---|---|---|---|---|
（金额统一展示单位；来源写 PDF 页码或"本次计算"）

## 经营与三表分析
（业务驱动 → 收入与利润 → 资产负债结构 → 现金流）

## 盈利质量与杜邦分解
（CFO/净利润关系、扣非/归母、杜邦三因子及驱动；计算口径与适用限制）

## 风险信号
| 信号 | 状态 | 证据 | 解释与关注点 |
|---|---|---|---|
（状态 ∈ 触发 / 已检查未发现 / 资料不足 / 行业不适用）

## 未验证事项与后续观察
（数据缺失、冲突、两轮回查未解决项、需要历史报告才能判断的问题）

## 来源与计算说明
（主要指标的计算公式与输入页码；OCR 或降级提取说明）
```

## 分寸要求

- 报告中分清"公司解释""原文数字""本次计算""分析判断"四类陈述。
- 部分提取失败时仍可交付，但必须在开头标注"分析不完整"，受影响指标和结论缺省或降级。
- 下载失败、文档不可读、公司/期间无法确认时输出失败说明，不输出貌似完整的分析。
- 每条 `report_claims.json` 的 claim 对应报告中的一句关键陈述；`validate_report.py` 通过后再做语义复核（因果解释是否充分、管理层说法是否被盲目采信）。
- claim.text 必须与正文中的句子或表格行一致，report_anchor 写该内容所在的完整 Markdown 标题。表格统一金额单位时，在 claim.display_unit 写明（例如“亿元”）。所有带数字的正文内容均需覆盖；标题、公司解释和推断中的数字同样检查。
- 无法计算、冲突或缺失的数据写成“资料不足”等文字，不能以数值参与结论。旧报告与旧台账若不一致，需要重新生成，不能直接复用旧版校验结果。
