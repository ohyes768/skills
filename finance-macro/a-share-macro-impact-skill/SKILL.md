# A 股宏观影响：未来四周

读取 Web 聚合 API，不重新抓取上游、不触发数据更新、不上传信号 API。默认展望分析日起 28 天；每周复用本 skill 更新判断，不自行创建定时任务。分析完成的报告按执行第 6 步推送到 RSS。

## 执行

1. 阅读 [分析框架](references/analysis-framework.md)；请求或排查数据时参考 [API 契约](references/api-contract.md)。
2. 运行 `python scripts/fetch_snapshot.py`（从本 skill 目录执行），读取生成的 `evidence.json` 与 `raw_snapshots.json`。默认自动采用服务端分析日期，探查近 12 个月，逐指标保留最近三个有效所属期；请求分析日前 7、14、21、28 天日频快照。可用 `--date YYYY-MM-DD` 指定日期，`--output-dir PATH` 指定新输出目录。
3. 先检查 `warnings`、原始 `quality` 和实际指标日期。缺失字段、未知状态或过期指标不得凭空补值。观察窗口不足时说明“无法确认趋势”。
4. 按“事实 → 经济含义 → 盈利／估值／风险偏好传导 → 反向解释 → 成立条件”形成未来四周判断。先判断整体，再分别分析成长和价值，最后比较相对倾向。
5. 如用户提供上次报告，或输出目录存在早于本次的报告，读取最近一份比较判断变化；没有则标为首次分析。保存 `report.md` 到本次输出目录，标注证据文件及分析时点，禁止覆盖历史报告。
6. 推送是必经步骤，不可省略：报告保存后运行 `python scripts/push_rss.py <report.md 路径> --title "<标题>" --insecure`。标题格式 `YYYY-MM-DD A股宏观展望｜偏支撑/中性分化/偏压制｜相对利于成长/相对利于价值/风格无明显倾向`，日期与正文分析时点一致，第二段方向词必须出现在报告正文。质量告警在返回的 `quality_warnings` 中显示但默认继续推送；仅当用户明确要求硬门禁时加 `--strict`。标题与已发布条目完全相同（同日重跑且结论未变）时脚本返回 `duplicate: true`，属预期行为，不要重推；结论变化会体现在标题中，不受影响。推送失败时报告仍保留在输出目录，修复后重试即可。RSS 推送成功后脚本会自动追加推送一份到 macro 报告看板，结果看返回 JSON 的 `report_push` 字段：`ok`/`duplicate`/`failed: 原因`/`skipped_no_token`（token 读 `finance-macro/.env` 的 `MACRO_SIGNAL_UPLOAD_TOKEN`，缺失只告警跳过，RSS 仍算成功）；`failed` 时重跑整个脚本即可，RSS 侧 duplicate 检测与 macro 侧幂等会挡住重复。

## 时间和证据约束

- 数据所属期不等于分析时点。本月未公布时使用最新已公布月，与前两期比较；各指标可以属于不同月份，逐项标注，不能统一冒称当月。
- 同比增速跨月变化写“百分点”，不是实际经济活动环比。PMI 写指数点；累计同比与单月同比不可混用。
- `data_date` 日期只用来识别记录所属期；若业务含义不清，称“标记月份”，不要断言为经济统计所属月。冲突记录在证据中保留并提示。
- 三个有效月份不一定连续。重复日期的日频回退只算一个观察点，不产生新变化；四个周度观察点不等于完整日线趋势。
- 不将 45 天作为所有指标统一过期线。结合正常发布节奏、`next_release_at` 与原始状态；未公布本月数据不自动降低置信度。下次发布时间已过只能提示核实，不足以证明实际漏更。
- API 历史月度值可能后修订，且分析日期不能证明当时已公布；历史指定日期只作回顾，不声称无前视偏差回测。
- 不把上游 score 跨卡相加；不套用旧固定权重或倒 U 型分数。不推断本 API 未提供的估值、盈利预期、指数表现或定价程度。
- 北向指标是成交额，不是净流入；南向是港股资金活动，不是 A 股直接流入。不得将二者方向误读。M1/M2 剪刀差与其组成项、利差与其组成利率不重复计票。

## 报告

开头标注分析时间、未来四周日期范围、最新月度所属期范围、日频实际日期范围。

1. **核心判断**：整体偏支撑／中性分化／偏压制；风格相对利于成长／相对利于价值／无明显倾向；较上期改善／不变／恶化或首次分析；把握高／中／低及原因。
2. **主要驱动**：挑选最有解释力的因素，逐条列值、日期、比较基期、变化单位、传导与反证，不强凑三个。
3. **整体与风格**：分别解释盈利、估值和风险偏好；成长与价值可同时受支持，不必二选一，不等同于具体行业。
4. **未来四周情景**：基准、转强条件、转弱条件；不编造概率、目标点位、仓位或确定跑赢结论。
5. **观察清单**：API 已提供的未来发布时间及待验证信号；日期缺失写“待确认”。数值触发线如属分析假设须明确标注。
6. **数据限制与复盘**：缺失、滞后、回退、日期冲突及其影响；与上次结论的变化和依据；不以宏观报告代替短线行情预测。

核心月度背景及金融条件均缺乏有效证据时，不给整体方向结论，输出数据缺口。局部缺失只限制对应判断；脚本或 API 失败时不生成看似有数据支持的报告。
