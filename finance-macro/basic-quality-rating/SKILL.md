# 基本面自动化评级

输入单只 A 股结构化财务 JSON，输出固定 10 字段 JSON，内含五维分项、星级与完整 Markdown 基本面说明。本 skill 仅有自动化分析流程，评分规则位于本 skill 及其按需参考中。

业务模式/护城河/行业前景/管理层先搜证、回答判别问题再落分；财务质量统一使用 F10 三表＋主要指标包，不做银行/保险专用取证。五维权重为 25/25/20/15/15，可评分时各维为 1-5 整数，证据不足无法定分时为 null。仅评价经营质量，不做估值、买卖或仓位建议，不访问调用平台、不写库或推送结果。

**v3 合同兼容性**：仍固定 10 个字段，但 dimensions 的值及 weighted_score/stars 允许 null。旧版仅接受整数的调用端须先适配未评级状态，再同步此版本；不得将 null 转为 0/1、丢掉未评分维度或回填旧星级。

## 输入合同（30 字段）

`code`、`name` 必须非空，code 是字符串，保留前导零。其余字段可缺失或为 null。金额单位元，百分数字段的 `15` 表示 15%，不是 0.15。0 和负值是有效数字，不当作缺失。不得把缺失、无效类型或非有限数值补成 0。

| 字段 | 含义 |
|---|---|
| code / name | 股票代码 / 公司名称，输出原样返回 |
| sw_level1 / sw_level2 | 申万一级 / 二级行业 |
| yield_2023 / yield_2024 / yield_2025 / avg_yield_3y | 各年及三年平均股息率(%) |
| dividend_count_2023 / dividend_count_2024 / dividend_count_2025 | 各年分红次数 |
| payout_ratio | 分红比例(%) |
| roe / roe_year | 最近年度加权 ROE(%) / 年度 |
| roe_avg_3y / roe_history | 三年平均 ROE(%) / 历年 `[{"year":2025,"value":15}]` |
| annual_net_profit_ex_non_recurring / annual_profit_year | 年度扣非净利润(元) / 年度 |
| net_profit_ex_non_recurring_yoy / net_profit_cagr_3y | 年度扣非同比(%) / 扣非三年复合增速(%) |
| previous_quarter_yoy_pct / previous_quarter_label | 上一季单季扣非同比(%) / 报告期 |
| latest_quarter_yoy_pct / latest_quarter_label | 最新季单季扣非同比(%) / 报告期 |
| debt_asset_ratio / gross_profit_margin | 资产负债率(%) / 毛利率(%) |
| shareholder_count / shareholder_change_pct | 股东户数 / 变动幅度(%)，仅作背景 |
| eps / eps_year | 摊薄 EPS(元) / 年度，仅作背景 |

不同年度、年度与单季分别引用，禁止把三年均值写成十年、把累计同比写成单季或把股息率当作业务质量。股息率、EPS、股东户数及毛利率单独缺失不机械扣分；仅在对应论断需要时记录缺口。

输入 code/name 缺失或互相矛盾且无法核实时，终止本次分析并说明具体输入错误，供调用方按失败处理；不发起交互追问，不编造可入库的评级结果。后文输出合同适用于身份有效的完整评级或灰色地带报告；证据不足不等于输入身份错误。

## 证据与缺失

A-D 使用当前可用的联网搜索/读取工具核实。优先公司年报、公告及交易所披露，其次券商研报、财经数据平台，最后媒体。重要论断按文末“来源输出”关联出处；引用媒体标明“媒体来源”。搜到摘要不能假装读过原文，历史案例不能直接当成当期结论。

财务 E 统一按 [F10基础财务入口](references/f10-financial.md) 执行。接受东方财富第三方数据，不逐项搜索官方原文、不补写银行/保险专用证据包。原始 stock.json 保持不变，其财务字段只作调用方背景；本轮 E 的数值来源是独立 f10-data.json。银行/保险采用有限的盈利基础规则，报告明确专用风险未评估，不能称为完整金融风险评级。

取证顺序统一为：已有结构化数据/接口候选 → 搜索定位来源 → 读取官方公告等可读网页正文核对。禁止下载、解析、截图或调用其他工具/skill 读取 PDF，也不复用 PDF 页级缓存作为本轮已核实证据。只有 PDF 链接时保留为待核实线索，改找同期间的官方 HTML 指标表、业绩发布或监管公示；搜索摘要不能代替正文，第三方接口候选不能直接当作官方确认值。网页正文缺表格、表头或脚注时，在原预算内定向搜索其他可读网页；仍缺核心事实则相关维度 null，不为给分转向 PDF。

全部脚本仅依赖 Python ≥3.12 标准库，路径以实际 skill 目录为准。常规执行见下文“固定计算与输出校验”，工具参数及输入解释见 [工具用法](references/tools.md)。仅部署维护时读 [安装与兼容迁移](references/setup-and-migration.md)。不加载旧 runbook、历史评分案例或第二套规则；工具故障报具体原因，不在分析中安装依赖或编写临时取数/计算工具。

### 网页取证边界

只使用已可用的搜索工具、正常网页正文读取/浏览器和本 skill 已支持的财务接口。可跟随页面公开链接及使用正常页面导航；网页只有空壳、附件链接、验证码或读取失败时，换其他可读来源，不将评级扩展成网站技术研究。

禁止下载或检索 JS bundle、source map、网页脚本配置来寻找接口；不通过浏览器网络记录/控制台挖掘 API，不猜测域名、网关、接口路径、参数或旧版页面地址，不扫描端口或批量探测 URL。接口开发与适配属于独立维护任务，本轮不做。一次正常网页读取失败后可用现成浏览器打开同一已知页面一次；仍无正文就结束该来源，在剩余轮次内换源，关键证据不足则 gap/null。

每次实际搜索或读取都须事先取得对应回执并登记结果，包括财务候选接口、浏览器读取、curl 和 execute_code 内的嵌套调用。一次搜索与后续每个页面读取分别计数；批量/并行请求按各子请求计数，不按外层工具调用算一次。当前账本不能表达一次批量操作的独立回执时，改为逐次取证，不在一个回执下循环抓取。已支持财务脚本的一次运行按一次取证调用计数，其内置有界请求/重试沿用脚本合同。禁止先抓取后补 start/result；这些是 agent 执行约束，脚本不会自动拦截外部操作。

### 财务复核范围

取数、期间、缺失与基础算分由 F10 工具执行，agent 解释返回的 checks/issues/limitations，不逐项重新取数、不推测缺失指标。不得用网页数字修改 F10 包。发现明显异常则披露并停止相关结论，交维护者处理，不在本轮开发适配器。第三方来源不冒充官方核验。

区分三种证据：独立披露原值可用于交叉核对；同一来源的重复转载只算同源；用输入参与倒推的结果只算代数自洽。比如用输入 Q1 增速推算 Q1，再以 H1−Q1 推算 Q2，不能声称已独立验证 Q1/Q2。不得为了给“已验证”背书而额外展开不影响判断的计算。

查不到证据不等于经营差。逐维区分已核实的经营弱项与尚未取得的资料：关键证据缺失、重大冲突未解而无法定分时，该维度为 null，不以 1/2/3 分占位，也不因资料少自动封顶。次要资料缺口若不妨碍按已核实证据定分，可以保留分数并解释影响；不能借此跳过本维关键判别问题。

任一维为 null，weighted_score、stars、boundary 均为 null，summary 以“灰色地带（证据不足，未评级）”开头；报告在对应维度写“未评分：证据不足”，watch_points 列出具体待验证问题。已核实的其他分项照常保留，不对已评分维度重新归一化，不输出参考总分、星级区间或隐含星级。所有维度均可评分时才产生整体评级。风险只写已证实的弱项或有依据的风险，资料缺口另列；补证后按同一标准重评。

报告开头简述信息丰富度 A（充裕）/B（有限）/C（稀缺）及依据，不增加顶层字段。它只描述本次资料覆盖，不影响分数或替代逐维判断。

## 取证完成条件与停止规则

开始任何公司材料读取前，先将本次原始输入保存为 stock.json，在唯一工作目录初始化 research.json：
`python3 <skill目录>/scripts/research_state.py init --state <工作目录>/research.json --stock <工作目录>/stock.json --providers <已有渠道ID列表> --research-limit 24`
新默认流程只初始化 A-D，不加 --bank-research/--insurance-research；F10 整体运行计入一次已有取证回执并登记结果，不按指标重复取数。续跑沿用原目录和账本，不先读取旧评级；可复用有来源/期间的旧证据，不能把历史分数当本轮依据，也不能研究结束后批量补造 start/result。

按 [有预算的取证](references/research-control.md) 执行 start → 宿主工具 → result → close：每次新搜索/读取前指定具体缺口及分档影响，登记真实结果后才继续；已有缓存事实直接 close --input，不伪造搜索回执。默认全局最多 24 次取证回执（含换源/重试），各维共享初查加四轮网页补查；开工可按宿主明确额度设更小预算，运行中不可增加。至少留 8 次宿主调用用于结案、计算、写草稿、语义检查及 finalize 修复；宿主剩余调用不足或发出即将耗尽警告时，立即停止取证，用已得事实 complete/gap 后交付，不能等强制收卷。脚本只统计它发出的回执，不知道宿主总调用余额，也不拦截绕过它的调用；不得声称已完成宿主强制接入。
余额不足、鉴权失败等渠道问题在本轮跨维度停用；临时故障优先换备用路径，同一渠道失败两次即停用。只配置现有能力，没有可用渠道时据已有证据 gap 收口，不临时安装环境、开发抓取工具或反复测试已知失败渠道。

本 skill 及按需参考包含评分标准，不加载其他 skill 或旧评分案例。先核实业务，再按下表建立简短证据清单（事实、来源链接/位置、期间、覆盖的问题、是否有冲突）；同一来源可以覆盖多个维度，不为每维重复下载。证据清单用于本轮工作，不加入最终 JSON 顶层字段。

| 维度 | 可结束取证的条件 |
|---|---|
| 业务模式 | 已核实主要业务/收入构成、客户与复购特征、定价方式和周期敏感度，能够回答本维判别问题 |
| 护城河 | 五类壁垒已逐项检查，核心优势的深度、持久性、变化方向及反证足以支持分档；无关类型不要求凑数，关键未知仍记缺口 |
| 行业前景 | 至少一个需求驱动及一个主要替代/下行风险已核查；没有发现反证时说明查过的范围，不宣称不存在风险 |
| 管理层 | 近五年关键决策及已知结果、资本配置/股东利益一致性、治理披露与接班问题已核查；区分已核实记录和未取得资料 |
| 财务质量 | 使用 F10 包计算，列明报告期、字段及缺口；金融企业必须展示基础评分范围限制 |

- 某维满足条件且无未解决的分档冲突，即标记完成。其后只复用证据，不因撰写报告而重新搜索或重读已核实段落。
- 每次追加搜索/读取前，指定一个尚未解决的问题，以及它可能影响的维度或评分依据；无法指出问题时不调用工具。已有来源先定位相关段落；命中后保存位置，不反复扫描全文。
- 每维共享一次初查及最多四轮定向网页补证，换问题名或关键词不重置预算；一轮指针对具体缺口检索并读取相关候选内容。仍缺关键证据则 close gap，写入 watch_points 并令该维 null。已有缓存事实可直接登记后 complete，无需强行搜索。
- 完成后仅因新的具体冲突可能改变分档才 reopen，每维只允许一次、额外一轮补证；旧证据不丢弃，仍无法裁决就披露冲突并 close gap。没有实证的“再确认一下”不重开。
- 所有维度进入“完成”或“证据不足未评分”后结束取证，进入评分和输出。

## A-D 评分：证据支持时为 1-5 整数，否则为 null

### business 业务模式（25%）

回答：客户多久购买一次、不买是否影响生活/经营？提价是否损失销量或客户？收入由量还是价驱动，下行周期有多敏感？服务业用合同续约/客户留存衡量复购，不套用消费品购买天数。

| 分 | 已核实的经营特征 |
|---|---|
| 5 | 必需性、高复购与强定价权均有证据支持 |
| 4 | 必需但低频，或品牌强的高端可选消费，经营模式可持续 |
| 3 | 周期性但长期需求存在，或成熟品牌增长受限 |
| 2 | 周期叠加替代风险，或不相关多元化削弱经营质量 |
| 1 | 强周期叠加重大政策/存续风险，模式脆弱 |

**2/3 分裁决**：先按最新已核实的收入/利润构成确定主导业务，不能只凭行业标签或某个子公司代表全公司。周期波动、价格接受者、缺乏定价权本身不直接判 2；主导业务长期需求仍有依据，且未证实其经营模式受结构性侵蚀时按 3 分档判断。判 2 需指出：主导业务因替代出现的持续需求收缩、客户/订单流失等具体证据，或不相关多元化已经造成资本配置损失、经营效率恶化等具体后果。仅有远期替代担忧、次要业务承压或业务板块数量多，不足以触发 2；行业趋势放到 industry 维度讨论。无法核实主导业务或侵蚀是否成立、因而无法定分时记 null 并记录争议，不编造确定的 2/3 分依据。符合 1 分严重存续风险条件时仍优先按原表处理。

### moat 护城河（25%）

逐项检查品牌/定价权、转换成本、网络效应、规模效应、技术与牌照，给出强/中/弱/无或证据不足的判断及依据，并说明优势过去五年变宽、稳定还是变窄。规模大不自动等于成本优势，拥有牌照不自动等于排他性。同一事实不能重复包装成多条优势。

评分看优势深度、持久性和变化方向，不按壁垒数量累计。回答：竞争者即使投入大量资本，仍有什么难以复制？优势如何体现在客户留存、定价、单位成本或竞争份额上？未来五至十年什么可能摧毁它？竞争者投入“100 亿”只作反事实追问，不作跨行业统一的金额门槛。

| 分 | 证据支持的竞争优势 |
|---|---|
| 5 | 多重优势相互强化，构成难以复制的体系，且有变宽的证据；罗列多项标签不足以支持 5 分 |
| 4 | 至少一条强护城河，深度、持久性及稳定性有证据支持；不要求再凑其他类型 |
| 3 | 已核实有竞争优势，但深度有限，或已有证据尚不能明确其变化方向 |
| 2 | 有具体证据表明核心竞争优势正在被侵蚀，而非仅因优势数量少、规模小或未找到资料 |
| 1 | 核查竞争格局与可复制性后，未见明显护城河；不能把未取得证据当作无优势 |

先按主导业务判断核心优势的状态。存在局部优势也不能掩盖核心护城河的持续侵蚀；判 2 须指出侵蚀事实及其影响。3 分的“趋势不明”以优势存在、当前作用及深度已有证据为前提，只是尚不能确认变宽或变窄；不能因为材料少而默认 3 分。若连优势是否存在、当前深度都无法判断，或稳定性疑问使关键分档无法裁决，按“证据与缺失”记 null。

### industry 行业前景（20%）

回答：未来 5-10 年需求变化的驱动及反证是什么？技术、政策、替代品如何侵蚀需求？把预测与已发生事实分开。仅有"老龄化""数字化"等标签不足以支持高分。

| 分 | 证据支持的需求与竞争趋势 |
|---|---|
| 5 | 长期增长驱动清晰，企业能受益，重大替代风险有反证 |
| 4 | 结构性增长明确，有政策或需求支持 |
| 3 | 成熟稳态，增长依赖结构升级 |
| 2 | 总需求见顶或替代正在侵蚀 |
| 1 | 持续衰退且有重大政策/替代压力 |

### management 管理层（15%）

回答：近五年重大并购/投资决策结果如何？资本配置有无回报？分红、回购、减持与股东利益是否一致？披露是否透明？接班是否清晰？以实际任期和公告核对人名，不能因未搜到负面默认"无重大问题"。

| 分 | 证据支持的治理表现 |
|---|---|
| 5 | 长期决策与资本配置优秀，透明且持续维护股东利益 |
| 4 | 有良好决策记录，透明且激励一致 |
| 3 | 已核查的记录一般，未见重大治理问题 |
| 2 | 激励不足、披露弱或有已核实的争议决策 |
| 1 | 已核实的重大治理风险或严重负面历史 |

**2/3 分裁决**：区分常规问询、已确认违规、重复违规和严重治理风险。问询函本身或收到问询并回复，不等于已确认违规，也不等于整改完成；同一事件被多个机构处理只算一个事件。

- 单次非重大披露差错，已明确完成整改，且在说明的后续核查范围内未发现同类再犯，可结合其他已核实治理记录按 3 分档判断，不能自动升到 4/5。
- 已确认的披露/资本配置问题仍未整改，或整改完成无证据，或不同事件中反复出现同类违规，按 2 分档处理，并列出事件、严重程度、重复性与整改状态。整改证据缺失只说明既有问题未被证实修复，不据此编造新的违规。重大治理风险仍按原 1 分档处理。
- 高分红、股东会高票通过或标准无保留审计意见，不能单独抵消披露违规；财务报表审计意见不能当作治理问题已解决的证明。各维按自身证据定分，不因“2 或 3 都不改变最终星级”反过来选分。

## E 财务质量（15%）：统一 F10 基础版

按 [F10基础财务入口](references/f10-financial.md) 一次获取三表和主要指标，使用返回分数。普通企业复用 ROE、负债、扣非盈利和趋势规则；金融企业只用三年加权 ROE、年度/相邻两季扣非盈利与 ROE 趋势，不套工业负债率阈值，不评估监管资本或偿付能力。缺核心指标则 E=null，不再启动金融专用网页取证。

新流程不加载 bank-financial.md、insurance-financial.md 或 financial-data-api.md；旧金融评分 CLI 仅兼容历史任务，不与本轮 F10 结果混用。新旧规则不同，不直接比较星级变化。

## 加权、星级、边界

仅当五维均为 1-5 整数时计算；任一维 null 则三个派生字段全部为 null，禁止均值填补或按剩余权重折算。整数计算 `total = business×25 + moat×25 + industry×20 + management×15 + financial×15`，`weighted_score = total / 100`。weighted_score 是供调用方校验的数字，report_md 与 summary 不展示这个小数总分。

星级下界为 1/2/3/4/4.5，分别对应 1–5 星。距任一档位分界 2/3/4/4.5 严格小于 0.25 时，脚本生成一句 boundary，枚举合法单维 ±1 后只描述确实能跨档的变化；其余为 null。量表端点 1/5 不是档位分界。复用脚本原文，不逐维列算式；整体未评级时 boundary=null，报告写“未评级，不计算边界”。

## 成稿与检查顺序

取证完成或确认未评分后，先固定一份简短结论清单：每维事实/来源、判别问题回答、分数与缺口，再调用带 --research-state 的 calculate 确定星级和边界，并保存该版五维快照、进入成稿阶段；有未裁决冲突就先按 null/灰色地带规则收口，不边写长报告边重新打分。

成稿后不再搜索、扫描旧全文或探索工具源码。只有新的具体分档冲突才先 reopen；预算耗尽则不再补查，将冲突维度 gap/null。仅调整已有证据下的分档理由不需要新搜索，但必须重新 calculate。任何维度变更都使旧快照失效；同步修改评分表、summary 和星级/边界，再 finalize。

以这份清单生成一次完整 report_md，并复用其中已定的结论形成 summary、risks、watch_points。报告作为数据写进 draft.json，使用已有 finalize 交付，不把整篇报告反复嵌进临时 Python 脚本或终端命令，也不为了序列化重新生成报告。

交付前集中做一轮语义检查：股票/期间和来源对应、五维分数与理由对应、未评分及冲突有明示、报告中的星级/边界与 calculate 一致，再运行 finalize 做结构检查。发现问题只改相关段落/字段，必要时重跑同一校验；不重写整篇、不重新搜索已完成证据。仅当发现错误公司、核心业务或关键来源失效等导致整篇依据不成立时，才允许一次完整重写，并沿用已有取证上限。若仍无法建立可靠依据，按输入错误终止或证据不足未评级处理，不无限重写。

## 固定计算与输出校验

1. 按 F10 参考生成 f10-data.json，读取 financial 的 score/checks/issues/limitations。
2. A-D 结案后将五维保存 dimensions.json，运行 `python3 <skill目录>/scripts/rating_math.py calculate --input dimensions.json --research-state research.json`。
3. 准备七个非派生字段的 draft.json。金融企业须在 report_md 和 watch_points 原样包含“基础财务评分：未评估监管资本、偿付能力、流动性及逐法人风险”。
4. 运行 `python3 <skill目录>/scripts/rating_math.py finalize --input draft.json --stock stock.json --check-financial --f10-data f10-data.json --research-state research.json --output rating.json`。成功原样交付 stdout 的十字段 JSON；失败仅修具体错误，不交付半成品。

finalize 重算财务及总分、核对原始身份与计算快照，但不证明来源真实性或报告语义；代理必须检查文字与数值一致。来源表将 F10 标明为第三方结构化数据并使用实际 URL、报告名、报告期、字段；调用方数据仅作背景，不能称为已独立核验。

## 输出合同（10 字段）

最终回复只有一个 JSON 对象，无代码围栏、前后缀或独立 Markdown。固定 10 个顶层字段，dimensions 恰为以下五键，分数为 1-5 整数或 null，五维齐全可评分时 stars 为 1-5 整数、weighted_score 为数字；任一维 null 时 stars/weighted_score/boundary 全部为 null，boundary 为字符串或 null，risks/watch_points 为字符串数组。字符串换行 JSON 编码为 `\n`，禁止 NaN、注释和尾逗号。scored_at、data_date 由调用方记录，不自行添加。

顶层字段恰为 `code`、`name`、`dimensions`、`weighted_score`、`stars`、`boundary`、`summary`、`risks`、`watch_points`、`report_md`；dimensions 恰为 `business`、`moat`、`industry`、`management`、`financial`。report_md 为包含下列内容的简体中文 Markdown 字符串：

1. **标题与日期**：`# 基本面评级：名称（代码）`；实际分析日期、信息丰富度及依据；可评级时写星级，未评级时写“灰色地带（证据不足，未评级）”，不显示星星。
2. **业务核实**：主营业务、收入来源与当期证据。
3. **五维评分表**：维度、分数、理由三列，各行回答本维判别问题；未评分项写“未评分：证据不足”及具体缺口；金融股/缺失/冲突限制写在相关行，不仅藏在文末。普通企业 E 列出 ROE/负债/年度与单季盈利/历史趋势；金融企业 E 列出基础盈利指标、F10来源及专用风险未评估限制，均说明期间、计算路径或未评分原因。
4. **星级与边界**：星级与 JSON 相同，boundary 原文复用；仅在已评级且 boundary 为 null 时写“非边界档位”；stars 为 null 时写“未评级，不计算边界”。
5. **结论与风险**：与 summary、risks、watch_points 一致；风险与缺口分别描述，不能把缺失说成已证实风险。
6. **证据来源**：按下节整理实际用于判断的来源，正文结论能对应到具体出处。

报告只评价经营质量，禁止目标价、买卖/仓位建议。输出前核对代码与名称、五维整数或 null、未评级传播、加权和、星级区间、真实跨档边界、所有缺失标注及报告一致性。

## 来源输出（放在 report_md 内）

正文中的关键事实、决定分档的依据及重要反证，在句末或评分理由中标 `[S1]`、`[S2]`。同一来源可支持多维，编号复用；分析推断要写明“据此判断”，避免把推断写成来源原话。不要求每句话附引用。

报告末尾用一个“证据来源”表，列为：`编号 | 来源 | 披露日期 / 事实期间 | 定位与支持内容`。
来源列使用 `[发布机构：原文标题](实际URL)`，直达实际读过的可读网页正文或结构化披露数据；接口无原文标题时用准确的资料名称。不用搜索结果页或无关首页代替具体出处。定位写能复查的栏目、表格或段落，不以未读 PDF 的链接或页码冒充网页定位。支持内容说明涉及哪维、哪个事实/关键数值，金融股还写集团/法人主体及单位。多条事实共用一页可合并，不复制整篇原文或整份行业证据包。

- **调用方数据**：使用独立编号 `[I1]`，来源列写“调用方结构化输入（未独立核验）”，不造外链或上游数据商名；列明实际财务年度、季度和输入的关键字段。输入未给数据日期时写“未提供”，不能把分析日当数据日。新流程 E 引用 F10 数据来源，此项只作调用方背景。
- **日期**：披露日期与事实所属期间分开。网页未标发布日期时写“未标注；访问于 YYYY-MM-DD”，保留已知事实期间；访问日期不冒充披露日期。仅缺页面发布日期不自动导致 null；若无法判断事实是否适用于本次分析，相关维度按关键证据缺口处理。F10 响应的披露/更新日期须按源字段记录，访问日不能代替。
- **来源层级**：标明公司/交易所/监管披露、研报、数据平台或媒体。转载同源不算独立核验。行业规则文档只支持规则解释，不能冒充公司当期经营证据。
- **没有取得的资料**：只有链接、摘要或访问失败的线索不能进入“已核实来源”表；若影响评分，在对应维度及 watch_points 写清缺口。全程没有外部可核实来源时，直接说明，表中只保留实际使用的输入，不凑编号、链接或来源数量。

仅列已用于结论或反证的来源，不设置最低篇数，不为填满表格重启已结案的搜索。research.json、行业证据包是工作文件；最终输出仍是十字段 JSON，来源编号和表格都编码在 report_md 内，不另加 sources 字段或在 JSON 后附链接。
