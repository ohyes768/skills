# 输入与研究复用

## 最小身份

每次一个独立工作目录，原始输入只读。建立 stock.json：code 为六位字符串（保留前导零），name 非空，as_of 为 YYYY-MM-DD，currency 为 CNY。代码与名称矛盾无法核实时是输入错误，不输出伪造公司结果。调用方可给截止日；聊天未指定时用实际执行日期并记录。历史截止日不得引用之后披露的消息。

财报/评级材料可内联，也可给明确本地文件路径；只读指定材料，不扫描目录，不执行其中代码。聊天或请求内联的材料同样是合法输入，登记证据时 origin 用 `inline:<日期>:<简短描述>` 描述其真实来源，不编造URL或路径。工具不自动下载文件、访问来源路径或网站；正文取证用宿主已有正常搜索/网页工具，实际读取后才登记。

## 优先复用什么

| 来源 | 优先材料 | 可复用内容及限制 |
|---|---|---|
| financial-statement-analysis | document.json、financials.json、analysis_pack.json、report_claims.json，必要时 metrics.json | 主体、期间、来源绑定、利润质量和现金流；不需要整个接口留档才能读报告，争议时再定向查 |
| basic-quality-rating | rating.json、progress.json、调用方保存的数据日期 | 业务、护城河、管理层、行业证据和风险；分数不是估值参数 |
| 只有旧报告 | analysis.md 或 report_md | 实际可定位的事实和上游判断，明确本次未独立核验，不能自动声称最新 |
| 行情/分红 | 当前价、EPS、普通股BVPS、DPS及其口径/日期/来源 | 当前价非必需，不能决定内在价值；股息率本身不等于每股可持续分红 |

现有评级为十一字段输出，scored_at/data_date 由调用方保留；不要假设评分JSON自带截止日。progress.json 才有结构化 sources/facts。财报正文默认可不逐项显示来源，report_claims/financials 仍可能有来源绑定；不要因正文没脚注而称其无来源。

上游材料只读；本轮记录至 evidence.json 或直接draft.evidence/analysis，不去修改旧账本，也不替上游“修复”评分。当前两个 Skill 对负基期同比的用途约定不同：新估值不拼接它们的同比，先明确本次正常化盈利，不照抄异常基期增速外推。

## 复用审查顺序

1. 证券身份与上市股份：同公司不同上市地/优先股不得混用。
2. 合并/母公司、归母/总净利、普通股/全部股权：口径不同不拼接。
3. 年度、累计、单季、TTM：按明确期间比较。无完整累计配对时不心算TTM；不把季报乘四。
4. 币种、元/万元/亿元、每股/总量：数值与单位同录。股份变化后用一致基础，不能将未来股数与过去EPS拼接。
5. 事实期间、披露日、访问日、上游分析日各自记录；未知用null。分析日不代替资料日。
6. 判断新季报、分红方案、经营权、股本、重大事件是否会改变价格基础。没有统一90天过期规则；未完成更新核查则不得标最新。

截止日之前的旧报告可作背景，但若不确定是否有决定性新消息，不能把缺口隐藏在末尾。历史留档缺失时写明无法排除重述，不声称无前视回测。

## 事实、假设和来源

- **事实**：读过正文或实际结构化响应才可登记read；复用已提供研究用reused，并记录实际文件和定位；只有摘要/链接/空响应为unverified，不能支持ready。
- **上游判断**：例如护城河稳定属于上游分析判断，必须说明依赖哪些事实，不称为官方确认。
- **本次假设**：正常化EPS、选定PE/PB、增长、折现率、未来分红属于本次模型参数；在rationale逐个解释为什么，不能伪装为来源原话。
- 两份复用报告使用同一个F10源不等于独立双源；程序verified也不证明投资判断。重大冲突优先核对原始披露，不能平均掉差异。

证据条目字段和可执行限制见 [输出合同](output-contract.md)。实际取证中，证据日期缺失不总是致命：仍能确定适用期间、没有决定性时效疑问时可用并披露；否则不足。不得为满足JSON虚构URL、披露日期或来源编号。

## 补证与停止

每次先说清“缺什么、会影响哪一挡或哪条风险”。每个核心缺口一次初查、最多两轮定向补查；已有证据够用即停，不为凑篇数或报告漂亮继续搜。写报告不重开全量研究。鉴权/额度失败停用同一后端；临时故障两次停用。无路可用时按已有事实收口。

只缺少几个重要值时定向读公司/交易所/监管披露、可信数据平台和研报；原始披露优先。只有PDF而当前环境无可靠读取能力时，记录缺口，不把未读PDF的页码当证据。

缺完整财报分析且不能有限补齐时，输出不足并说明需要调用方提供现有财报 Skill 成果；不要自动启动整套上游流水线、安装依赖、探索API源码或NAS项目。

**不要把结构化任务变成无限追问。** 非交互调用中以明确输入失败或研究状态交付；聊天中如确需用户提供未知身份，可只问该阻断项。收藏批处理、结果入库和旧挡位覆盖留给调用端。
