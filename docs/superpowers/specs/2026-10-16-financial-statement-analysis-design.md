# A 股财报 PDF 分析 Skill：流程设计草案

日期：2026-10-16。状态：供审阅的设计草案，未实现 skill 或脚本。

## 1. 目标与范围

用户提供一个财报 PDF 链接，skill 下载原文、定位重点章节、提取可追溯数据、计算指标，并输出中文 `analysis.md`。第一版以 A 股非金融企业为主，优先支持年度报告全文，同时识别半年报、季报和年报摘要并按实际披露范围降级。

默认只使用该 PDF 及其中的比较期数据，不自行抓取历史财报、股价、券商预测或行业数据。因此输出聚焦财务表现与风险，不自动提供估值、目标价或买卖建议。未来可以显式增加历史财报链接参数。

银行、保险、证券公司需要独立的行业指标体系。第一版识别后仅提供适用的基础信息、披露事项与局限说明，不套用一般企业的流动比率、存货周转和通用评分，不宣称完成行业深度分析。

必填输入只有 `pdf_url`。可选输入包括输出目录、关注问题；公司、代码、报告类型和期间尽量从原文识别。默认输出中文完整分析，不要求用户先填写公司元数据。

## 2. 实现路线与推荐

| 路线 | 做法 | 取舍 |
|---|---|---|
| 推荐：本地提取与计算，模型分析 | 全文建立页码索引，重点页提取，结构化数据经脚本校验后交给模型分析 | 证据与计算可复核；需要维护章节和财务科目映射 |
| 全文转 Markdown 后直接分析 | 转换整份文档，把全文交给模型 | 原型简单；长文上下文成本高，表格错列和遗漏附注较难控制 |
| 外部文档解析服务 | 由服务识别版面、OCR 和表格，再进入相同分析流程 | 可作为复杂文档的后续选项；增加服务依赖、调用成本和数据上传步骤 |

第一版不引入向量数据库和多代理系统。单份 PDF 可以用页码索引、章节检索和有界回查完成任务。

## 3. 数据流及模型边界

```text
PDF URL
  → 下载与原文校验
  → 文档识别、全文轻量页码索引
  → 重点章节清单
  → 文字、原始表格及页面证据
  → 模型映射财务科目，生成标准化事实
  → 脚本校验与指标计算
  → 模型分析并按问题回查附注
  → 结论与证据一致性检查
  → analysis.md
```

脚本负责下载、页码索引、原始提取、标准化数据的算术校验与指标计算。模型负责语义章节判断、科目映射、解释证据和撰写报告。不能假设一个通用正则脚本能够正确理解所有公司的报表。

本地保存全文索引不等于把全文送入模型。模型按章节读取证据；跨章节事实用结构化数据衔接。PDF 中的内容仅作为资料，不执行其中要求调用工具、上传文件或修改系统的指令。

## 4. PDF 下载与文档识别

1. 接收 HTTP/HTTPS 链接，支持正常重定向和不以 `.pdf` 结尾的有效 PDF 地址。
2. 流式下载到本次运行目录；检查 HTTP 结果、文件头及 PDF 实际可打开性，避免把登录页、错误页保存为财报。
3. 设置超时和文件大小上限，临时网络失败至多尝试三次；记录最终 URL、下载时间、文件大小、SHA-256、可用的 ETag/Last-Modified。
4. 缓存按内容哈希复用；同一 URL 的文件更新时重新识别，解析缓存还应关联解析器版本与选项。
5. 从封面、目录、正文和报表表头交叉识别公司、代码、报告年度、报告类型、币种、会计准则、披露日期及是否为修订版。文件名不作为唯一依据。
6. 判断全文/摘要、原生文字/扫描/混合文档、页数、书签及是否加密。身份或期间冲突必须暴露给报告。

HTML 或失效链接返回明确的获取失败信息，不继续生成虚构分析。加密 PDF 需要合法密码；缺少密码时停止读取。

## 5. 全文轻扫与重点章节定位

先遍历全文的文字层，保存每页标题候选、文字块、关键词命中、字符质量和物理页码，不对全文逐页做昂贵的表格或图像分析。

定位优先顺序：PDF 书签 → 印刷目录及目标页核验 → 全文标题与关键词 → 模型判断候选页。对目录页、正文标题和表格结构交叉验证，避免把管理层讨论里提到的“现金流量表”误认成报表正文。

章节不写死为“第十节”等编号。目录页码、PDF 阅读器页码、文档印刷页码分别保存；通过目标页核验建立对应，不能假定整份文档只有一个固定页码偏移。所有引用以从 1 开始的 PDF 物理页码为基础。

| 优先级 | 章节或材料 | 提取目的 |
|---|---|---|
| 必读 | 封面、目录、主要会计数据和财务指标 | 公司与报告识别，关键数据、扣非利润及追溯调整情况 |
| 必读 | 管理层讨论与分析 | 业务与分部、收入成本变化、产品和地区结构、重大变化解释 |
| 必读（如有） | 审计报告 | 意见类型、持续经营重大不确定性、强调事项、关键审计事项 |
| 必读 | 合并资产负债表、合并利润表、合并现金流量表 | 分析主体及比较期数据，避免误用母公司报表 |
| 初筛后精读 | 重要事项 | 资金占用、担保、重大诉讼、关联交易、承诺等重要事项 |
| 按需回查 | 合并所有者权益变动表 | 分红、股东交易、其他综合收益、净资产变动及利润勾稽 |
| 按需回查 | 会计政策、估计变更、差错更正、合并范围 | 判断可比性、重述和异常解释 |
| 按需回查 | 财务报表项目附注 | 收入确认、应收账龄与减值、存货、现金限制、债务期限、商誉等 |
| 低优先级 | 履历、一般性治理文字、装饰页面等 | 保留可检索索引，出现与分析相关的问题时再读取 |

“必读”表示必须寻找并记录结果，不表示每种报告都必然披露。例如季报没有审计报告不能自动视为风险。

扫描 PDF 不能靠空白文字层定位章节：有可用目录时先 OCR 目录并核验目标页；没有可用目录时需要逐页做轻量 OCR 以发现章节，再对关键页高质量提取。混合文档按页面或区域判断，不能只因某页已有页眉文字就跳过其中的扫描表格。预算耗尽仍无法定位时报告提取不完整，不冒充完成全文检查。

## 6. 正文、表格与页面证据提取

推荐以 PyMuPDF 读取书签、文字块与页面坐标；财务表格在目标页使用原生表格提取，并以 pdfplumber 做备选或辅助校验。扫描或文字损坏的关键页使用中文/英文 OCR；OCRmyPDF/Tesseract 是可选依赖，执行前检测可用性。视觉读取用于疑难表格的核验，不默认替代全部本地提取。

原生提取失败后按页降级：其他表格策略 → 页面渲染后 OCR/视觉复核 → 标记缺失。转换器或 OCR 可用不代表数字已经正确。

需要保留：

- 科目原文、表头、币种、单位、日期和期间列，不能只保留一串数字。
- 表格跨页续表、重复表头、行列坐标；拼接前核验列定义一致。
- 括号负数、负号、小数点、千分位和空白。破折号或空白是否为零须依据表格语义，无法判断时留空。
- 原始页码、表格或文字块编号、来源摘录；有疑义时保留页面或裁剪图。

最终摘要使用的关键数字、全部风险信号所依据的数字，以及任何校验冲突项，都需要回看原表或页面图核验。发现 OCR 的 0/O、1/l、负号或年度列错误时不能凭“看起来合理”直接修正。

## 7. 标准化事实层

`financials.json` 应保存数值与证据，而不是只有给模型阅读的散文。每个观察值至少包含：

| 信息组 | 必需内容 |
|---|---|
| 科目 | 标准科目键、原文科目、所属报表或附注 |
| 数值 | 原始文字、原始单位、币种、标准化数值；金额统一为元，比例、每股数据等保持独立类型 |
| 时间 | 时点或期间、起止日期、年度/半年/季度、单季或累计、当前或比较期 |
| 范围 | 合并或母公司、集团净利润或归母净利润、全部权益或归母权益 |
| 版本 | 本期披露、比较期是否重述、调整前后版本；本次分析采用哪个版本及理由 |
| 来源 | 文档哈希、PDF 物理页码、印刷页码（如有）、表格/文字块及原始摘录 |
| 状态 | 原生提取/OCR/视觉读取、是否已复核、缺失/歧义/冲突原因 |

缺失与零分开；原文报告值、脚本计算值和模型推断分开。模型不自行赋予貌似精确但未经校准的置信度百分比，可使用“已核验、存在歧义、缺失”等可解释状态。

A 股关键约束：

- 默认分析合并口径，母公司数据单列；存在疑义时不自动替换。
- 归母、集团净利润、扣非归母净利润分别记录，不能互换。
- 半年和前三季度累计值不能当单季；只有同口径累计数据齐备时，才允许相减得到单季并标记计算来源。
- 利润表、现金流量表看同比期间；资产负债表比较的是期末时点，期末对年初不标成同比。
- 比较期采用本 PDF 清楚披露的可比重述口径；不混用调整前后值。
- 年报中的历史摘要可用于其确实披露的指标，不视为已取得过去年度的完整三表和附注。

## 8. 计算与校验

全部派生数字由脚本计算，保留公式、输入事实 ID、口径和结果状态。

校验至少包括：资产 = 负债 + 权益；利润表适用分项合计；现金及现金等价物期初到期末的变动与经营、投资、筹资及汇率影响等披露调节项的一致性；财务摘要与报表正文的同口径交叉核对。

现金勾稽不能直接用资产负债表“货币资金”代替现金及现金等价物。净利润也不能直接等于留存收益增量，需考虑股利、重述及其他权益变动。存在现金流补充资料时，优先按其完整调整项目验证利润到经营现金流的桥接。

容差依据原文计量单位、精度和分项数量设定，不使用固定“相差大于 1 就有问题”。冲突先检查页码、列映射、合并范围、单位与附注解释；未解决时标记数据冲突，不直接指控会计造假。

第一版指标分组：

- 增长与盈利：营收、集团/归母/扣非归母利润及同比，毛利率、净利率、费用率，分部贡献。
- 盈利质量：经营现金流与集团净利润的关系、扣非归母/归母、应收与收入变化、减值与一次性收益。分子分母口径相符才计算。
- 资产与负债：资产负债率、一般企业适用的流动和速动比率、债务期限、受限资金、应收和存货质量、商誉与资本化。
- 现金与投资：三类现金流、主要投资和融资用途；自由现金流采用 `经营现金流 - 购建固定资产、无形资产和其他长期资产支付的现金` 的明确简化口径，不能把投资现金流净额当资本支出。
- 运营效率与杜邦：存货/应收周转，使用可取得的平均余额；集团口径简化 ROE = 集团净利润/平均总权益，分解为净利率 × 总资产周转率 × 权益乘数，整条公式使用相同范围和期间。与公司披露的归母加权平均 ROE 分列，不伪装为同一指标。

基期或分母非正、接近零、平均余额缺失时输出不适用及原因，必要时描述利润额变化或扭亏/转亏。非全年数据不默认年化；缺少足够比较期就不下“持续改善/恶化”的结论。

## 9. 分析及附注回查

保留参考 skill 的三表、盈利质量、杜邦和风险信号主线，补上经营背景、数据质量及证据引用。

| 初始发现 | 下一步查证 | 结论要求 |
|---|---|---|
| 应收增长明显快于收入 | 账龄、坏账准备、客户集中度、信用政策、并表变化 | 区分扩张、结算节奏与回收风险 |
| 存货增加、毛利率下降 | 库存构成、跌价准备、产销与管理层说明 | 不把增加存货直接认定为积压 |
| 利润增长但经营现金流走弱 | 现金流补充资料、经营性应收应付、税费及一次性项目 | 解释利润与现金的差异；资料不足则说明 |
| 货币资金与债务同时较大 | 受限资金、现金等价物、存款地点、利率与到期结构 | 结合可用资金和偿债期限判断 |
| 归母与扣非利润差异大 | 非经常性损益披露、补助、处置和公允价值等项目 | 使用披露的分类，不能把全部其他收益等同非经常性损益 |
| 商誉、资本化或在建工程突出 | 减值测试、资本化政策、项目进度及后续支出 | 金额、解释和未验证项分别呈现 |

每个风险项目输出“触发、已检查未发现、资料不足、行业不适用”之一，并附事实、可能解释和下一步关注点。关键审计事项不自动等于非标准审计意见；无保留意见中的持续经营事项仍需单列。

参考中的行业通用阈值仅可转化为待校准的筛查线索，不能成为自动定性规则；红旗数量不能换算成造假概率。第一版默认不生成综合分数，采用有证据的分项评价，同时单列资料覆盖情况。若以后增加评分，需先确定行业、可计算指标、缺失处理和验证样本。

回查不是无限循环：对影响核心结论的歧义最多进行两轮定向补提取，仍未解决就保留不确定性并降级相关结论。

## 10. Markdown 交付约定

主交付物只有 `analysis.md`；运行目录保留 PDF、页码索引、重点章节、标准化事实、指标和校验结果，便于复核与重跑，不默认全部展示给用户。

建议报告结构：

1. 公司、报告期间、来源链接、币种和口径、全文/摘要、分析覆盖情况。
2. 核心结论：经营变化、盈利质量、现金与偿债、主要风险，控制在数条有证据的判断。
3. 关键指标表：本期、比较期、变化、来源；金额统一展示单位。
4. 经营与三表分析：业务驱动、利润、资产负债及现金流。
5. 盈利质量及杜邦分解：计算口径、驱动及适用限制。
6. 风险信号表：状态、证据、解释、关注事项。
7. 未验证事项与后续观察：数据缺失、冲突、需要额外历史报告的问题。
8. 来源页码索引及关键指标计算说明。

关键事实随文引用 PDF 来源及页码；支持时可使用原始 PDF URL 的 `#page=N` 锚点，并写明“PDF 第 N 页”。计算结论引用其输入数据的页码，推断明确说明推断依据，不为推断伪造原文结论。

报告中分清“公司解释”“原文数字”“本次计算”“分析判断”。不写入未披露的预测值，不因为输出模板有一列未来年度就自行预测。

部分提取失败仍可以生成标注“分析不完整”的报告，但受影响的指标和结论必须缺省或降级。下载失败、文档不可读、公司/期间无法确认时返回失败说明，不输出貌似完整的分析。

## 11. 拟定的 skill 组织

以下为拟定文件边界，本轮不创建这些实现文件：

```text
finance-macro/financial-statement-analysis/
  SKILL.md
  scripts/
    fetch_pdf.py              # 下载、原文校验、来源元数据
    inspect_pdf.py            # 页码索引、文档类型、章节候选
    extract_sections.py       # 指定页的文字、表格、OCR 与页面证据
    calculate_metrics.py      # 标准化事实校验、指标与公式来源
    validate_report.py        # 事实引用与数值检查；语义由模型另做审阅
  references/
    analysis-framework.md     # 财报分析逻辑、指标适用条件、风险解释
    extraction-rules.md       # A 股章节、科目映射和期间/单位规则
    report-template.md        # Markdown 输出约定
```

`SKILL.md` 保持简洁：触发条件、输入输出、运行顺序、脚本与模型职责、质量门槛、按需参考资料。复杂分析规则和提取规则放入 references，按步骤加载。依赖与运行方式在实现时按本仓库 Python 项目约定声明并锁定；OCR 作为能力可检测的可选依赖。

运行产物建议放到独立的用户指定输出目录；默认置于仓库既有 `finance-macro/output/financial-statement-analysis/<run-id>/`，不放进 skill 源码目录。

## 12. 开发后验收

至少覆盖：文字版完整年报、跨页报表、混合/扫描 PDF、带追溯调整的报告、半年/前三季度累计数据、亏损或零分母、年报摘要、特殊审计事项、金融企业路由及无效链接。

验收先人工标注样本中的公司/期间、三表关键字段、单位和页码，再比较提取与计算结果。重点检查：

- 摘要引用的关键数字均能回到正确的原表与期间，单位正确；存在歧义的值不进入无条件结论。
- 相同 PDF 和版本的提取及计算结果可复现，金额与公式符合精度要求。
- 不混用合并/母公司、归母/集团、季度/累计、调整前/后数据。
- 单份 PDF 缺少足够历史时不产生连续趋势、审计师频繁更换等未经验证结论。
- 缺失审计、OCR 失败和行业不适用时按约定降级，不把未检查项目写成未发现风险。
- 报告覆盖参考分析主线，并能说明重大数字变动背后的证据与限制。

本轮未运行真实 PDF 的下载、提取或效果评估；上述为后续实现的验收标准。

## 13. 调研来源

- 参考分析主线：[HKUDS/Vibe-Trading financial-statement](https://github.com/HKUDS/Vibe-Trading/blob/main/agent/src/skills/financial-statement/SKILL.md)。该参考主要提供财务分析规则，不包含本设计的 PDF 数据处理流程。
- 原生文字、坐标及表格能力：[PyMuPDF 官方文字提取文档](https://pymupdf.readthedocs.io/en/latest/recipes-text.html)。
- 表格提取及可视化调试：[pdfplumber 官方仓库](https://github.com/jsvine/pdfplumber)。其说明指出更适合机器生成的 PDF，不能据此假设可直接识别扫描财务表。
- OCR 降级能力：[OCRmyPDF 官方高级功能文档](https://ocrmypdf.readthedocs.io/en/latest/advanced.html)。OCR 文字层不自动等于正确的结构化表格。
- A 股年度报告结构的官方入口：[证监会年度报告内容与格式公告](https://www.csrc.gov.cn/csrc/c101954/c7547588/content.shtml)。实现时按实际文档标题定位，不依赖章节编号。
