## 新增 PITFALLS

### PITFALL #28 — 招股历史价格 vs 当前价格混叠（"earlier draft 误判为 current"）

**触发场景（09856）**：web_search 返回结果中既有"招股价 95.30–101.70 港元"（实际是 09615 梅卡曼德机器人的价格，搜索 snippet 误聚合），又有"招股价 16.00–17.42 港元"（实际是 2026-03 第二次递表时的早期区间，已被官方 32.96 港元定价覆盖），还有"招股价 32.96 港元"（9/14 早间官方公告，**唯一正确**）。

**症状**：模型容易把搜索 snippet 第一条 / 最高排名的数字当 current；尤其当旧价格区间（95–101 或 16–17）出现在权威媒体（雪球、网易、新浪财经）的旧标题里。

**应对**：
1. **官方定价公告时点优先**：HKEX 披露易 / 港交所招股公告 / 招股说明书附录 > 一切旧报道。当前 IPO 公告日期 ≥ 招股期开始日 → 公告时点 ≤ 招股期开始日的报道一律视为旧版。
2. **HKEX announcement PDF 反爬（CORS / 404）抓不到正文**（PITFALL #2），所以 official 定价只能用 web_search 拿；**搜索 query 必须包含公司名 + 当前月份 + "招股" + "港元"**（如 `"纳真科技" 9月14日 2026 招股价 港元`），过滤掉旧月份（"3月"、"5月"等）的报道。
3. **价格区间 vs 单一价**：HKEX 招股公告若用"每股发售价"+"每手 X 股"句式 → 单一价（如 09856 的 32.96 港元）；若用"招股价区间"+"介乎 A 港元至 B 港元" → 区间价（如 06727 的 49–61 港元）。**两者写法不能混用**，混用即表示源数据错误。
4. **第三方（jisilu / daily_rss_report.py）的 `price_range` 字段不可信**：09856 jisilu 显示 `"32.96-32.96"`（单一价），而 06727 显示 `"49-61"`（区间）；当 jisilu 与 HKEX 官方公告冲突时，**以 HKEX 公告为准**（jisilu 是事后回填，存在更新延迟）。
5. **历史验证**：2026-09-14 web_search 09856 第一波返回的"95.30-101.70 港元"实际是 09615 梅卡曼德的价格（同一搜索词被搜索引擎聚合）—— 必须从标题 / 来源 URL 二次核验公司名匹配，不能直接采信 snippet 数字。

### PITFALL #29 — A+H 二次上市票的 H 股定价区间下限 / 入场费 / 每手可能在招股首日未公开

**触发场景（06700）**：四方精创 9/14 早间官方公告只披露**最高发售价 ≤ 16.00 港元**，区间下限、每手股数、入场费均未在公开媒体明确披露。

**症状**：A+H 二次上市票招股首日，A 股母公司已上市多年，H 股招股书才刚生效；**HKEX 招股章程 PDF 反爬抓不到**（PITFALL #2），公开媒体（智通财经 / 360kuai / 新浪财经 / 财联社）只转述官方公告摘要（最高价 + 规模 + 保荐人），常常漏掉区间下限、每手、入场费。

**应对**：
1. **入场费临时估算公式**：`入场费 ≈ 招股价 × 每手股数`；每手股数按 H 股惯例 100 / 200 股中常见值估（金融 IT / 银行 IT 票多用 100 股或 200 股）。
2. **明确标注"未在公开媒体披露"**：报告里写"每手 / 入场费 / 区间下限暂缺（已核验：360kuai / jrj.com.cn / 新浪财经 / 智通财经 / 财联社）"，避免编造数字。
3. **AAStocks per-code 兜底**：`https://www.aastocks.com/tc/stocks/market/ipo/upcomingipo/company-summary?symbol=<5位CODE>` 抓入场费表（即便 SSR HTML 经常为空，可仍尝试一次）。
4. **不影响评分**：把"数据置信度 -2~-3"写进评分，但**报告仍可推送**——只需保留 `quality_warnings: 财务基本面 ...` 即可。
5. **历史验证**：2026-09-14 06700 四方精创 + 09856 纳真科技均为招股首日报告，每手 / 入场费 / 区间下限均暂缺；06727 星环科技（招股倒数第二日）三字段已三源核验 → 招股期推进后字段逐步可获。
