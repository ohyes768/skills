## 关键经验

1. **web_extract 不可用时的降级路径**：本批实测 `web_extract` 返回 `SearXNG is a search-only backend and cannot extract URL content. Set web.extract_backend to firecrawl, tavily, exa, or parallel.`（2026-09-17 首次出现错误信息）。**应对**：立刻降级到下一波 `web_search` 加更具体的 query（如加 "基石" "毛利率" "现金流" 等关键词让搜索引擎直接返回 snippet 中的关键数字），不要再 retry `web_extract`。3 次 `web_search` 通常可以替代一次 `web_extract` 失败的页面。
2. **A+H 票招股期推进后字段补齐**：06700 A+H 票在 9/14 招股首日三字段（每手 / 入场费 / 区间下限）暂缺（按 PITFALL #29），到 9/17 招股最后一天已三源核验通过（jisilu + 招股章程 URL + 招股 PDF）→ **字段可获性与招股期天数正相关**，招股期 ≥ 4 天的票在最后一天通常三字段齐备。
3. **批量研究时 web_search query 设计原则**：每只标的先用 1 个宽泛 query（公司名 + 招股 + 基石 / 营收）拿到主要定性框架，再用 5-6 个针对性 query 分别挖 PITFALL #31 的 7 类信号 + PITFALL #18/#20a/#21/#24/#26 必备字段。**每只 ≤ 8 个 web_search query 即可覆盖**——本批 09856 共 7 个 query，06700 共 6 个 query。
4. **评分落地**：本批 09856 = 58 C+，06700 = 45 C-。**两面验证评分规则**：
   - 热度高 + 基石阵容强（24 名占 ~47%）≠ 评分一定要 A/B，需考虑 PITFALL #18/#24/#26/#27 等风险调整
   - 热度低 + 治理风险高（A+H 信披打架 + 实控人减持 >7 亿）→ 评分自然落入 C 级以下
   - **0.618 比例观察**：本批评分（58 vs 45，差 13 分）反向印证热度评分与基本面评分的独立性——单看孖展 09856 比 06700 高 5 倍，但基本面风险更显著，最终评分差距远小于热度差距。
