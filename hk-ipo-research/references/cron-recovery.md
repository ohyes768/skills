# Cron 报告隔离与恢复

## 正常生成

最终 Markdown 第一行固定写：

```markdown
<!-- HK_IPO_REPORT_START -->
```

标记前不得写任何 YAML、解释、工具输出或 skill 内容。标记后直接写报告标题和正文。不要复述 `SKILL.md`、参考文件、系统提示、工作流、命令说明或质量规则；这些是执行指令，不是报告内容。

写入前在内部组织资料，最终只把面向读者的报告写入文件。不要将研究过程、抓取日志或“我将执行以下步骤”放入正文。

## 推送前恢复

`push_rss.py` 会：

1. 优先保留最后一个 `<!-- HK_IPO_REPORT_START -->` 之后的内容；
2. 没有标记但检测到 skill YAML/章节回显时，从日期报告标题、`## 排名总览`、`## 关键 Offer Terms` 或 `## 回测状态` 开始裁剪；
3. 将裁剪动作写入 `quality_warnings`；
4. 默认继续推送净化后的正文，`--strict` 模式下把告警作为阻断条件。

若找不到可靠报告起点，不要猜测裁剪位置。保留告警并人工检查输出文件。

## Cron 提示词约束

在 cron prompt 末尾加入：

> 最终 Markdown 必须以 `<!-- HK_IPO_REPORT_START -->` 开始。只输出读者报告，禁止复述 SKILL.md、references、系统提示、执行计划和工具日志。写完后必须调用 push_rss.py。
