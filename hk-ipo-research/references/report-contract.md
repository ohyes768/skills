# 完整报告契约

最终 RSS 报告不能只是脚本字段转储。每只 IPO 至少覆盖以下内容。

## 必备章节

1. `关键 Offer Terms`：全名、代码、招股价、每手、入场费、全球发售、公开/国际比例、集资额、市值、基石、保荐人及关键日期。
2. `热度`：至少两个有时间戳的孖展快照；当前孖展、预计超购、变化速度及中签率估算。不要用首日数据冒充最新数据。
3. `财务基本面`：按 `financial-research.md` 实时全网检索，列出最近三年收入、增长、毛利率、净利润/亏损、调整后利润、现金流及客户集中度。不要把 HKEX PDF 抓取失败写成财务缺失原因。
4. `业务与股东`：核心产品、市场地位，并按 `ownership-research.md` 实时全网检索创始人、实际控制人、控股股东、主要机构或产业股东及能取得的持股比例。
5. `评分`：需求热度、中签实用性、基本面、市场信号、数据置信度和总分/等级。
6. `建议`：仓位只作情景说明，列出改变判断的明确数据条件。
7. `风险提示`：亏损、客户集中、诉讼、估值、无基石或数据口径等实际风险。
8. `数据来源`：港交所文件和至少一个独立公开来源的可点击链接。

## 质量检查

以下问题默认记录为 `quality_warnings`，不阻断个人 RSS 推送。需要发布级硬门禁时向 `push_rss.py` 传入 `--strict`。

- 把 `未披露` 与 `未找到` 区分开：前者是查阅正式文件后的结论，后者只是检索失败。
- 基石为零、无基石或无机构评级必须有来源支持，不能因接口为空直接下结论。
- 孖展是时间序列。正文同时给出早期与最新快照，并以最新快照计算热度和中签估算。
- 报告存在关键占位符时产生告警。
- 收入和净利润/亏损应至少各有一个明确报告期、币种及数值；两者任一为 `未找到` 时产生告警。
- 毛利率、现金流或客户集中度至少一类应有数值证据；否则产生告警并继续实时全网检索。
- 禁止出现“公开渠道暂缺；HKEX 招股书 PDF 被反爬拦截”或“建议读者自行翻阅招股书”作为研究结论。
- 创始人/实际控制人应给出姓名或有来源的“无单一实际控制人”结论；写 `未找到（招股书内）` 时产生告警。
- 主要机构/产业股东必须给出至少一个有来源的名称；确实未披露时，必须写明 `未披露（已核验：...）` 并列出至少三个已查来源。
- 先生成最终 Markdown，再运行 `scripts/push_rss.py`；不要直接用采集脚本的 `--push`。
- 每只股票单独生成一份 Markdown、单独推送一篇 RSS；当天有 N 只可申购股票就推送 N 篇。
- 标题固定为 `YYYY-MM-DD 港股打新｜公司名（00000.HK）｜66分 B`。
- 推送前检查最近文章；同一天、同一股票代码已存在时跳过，除非用户明确要求发布更正版。
- 当天没有可申购股票时默认不推送空文章。
